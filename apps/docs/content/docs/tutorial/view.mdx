The `@nest-boot/view` module provides a configured [LiquidJS](https://liquidjs.com/) `Liquid` instance through Nest dependency injection. LiquidJS resolves templates on demand, including layouts and partials.

## Installation

```bash
npm install @nest-boot/view liquidjs
# or
pnpm add @nest-boot/view liquidjs
```

## Static Module

Import `ViewModule` directly to use the defaults:

```typescript
import { ViewModule } from "@nest-boot/view";
import { Module } from "@nestjs/common";

@Module({
  imports: [ViewModule],
})
export class AppModule {}
```

The default LiquidJS options are:

```typescript
{
  root: ["views/"],
  partials: ["views/partials/"],
  layouts: ["views/layouts/"],
  extname: ".liquid",
  outputEscape: "escape",
}
```

These paths are resolved from the application's current working directory. Interpolated values are HTML-escaped by default; use LiquidJS's `raw` filter only for content you trust. A typical layout is:

```text
project/
├── views/
│   ├── emails/
│   │   └── welcome.liquid
│   ├── layouts/
│   │   └── email.liquid
│   └── partials/
│       └── signature.liquid
└── src/
```

## Dynamic Module

`register()` accepts any LiquidJS `LiquidOptions`. Options you provide override the defaults individually:

```typescript
import { ViewModule } from "@nest-boot/view";
import { Module } from "@nestjs/common";

@Module({
  imports: [
    ViewModule.register({
      root: ["templates/"],
      partials: ["templates/includes/"],
      layouts: ["templates/layouts/"],
      extname: ".html",
      cache: true,
      strictVariables: true,
    }),
  ],
})
export class AppModule {}
```

Pass `isGlobal: true` alongside the LiquidJS options when the configured engine should be available application-wide.

## Asynchronous Dynamic Module

Use `registerAsync()` when options depend on another provider:

```typescript
import { ViewModule } from "@nest-boot/view";
import { ConfigService } from "@nestjs/config";
import { Module } from "@nestjs/common";

@Module({
  imports: [
    ViewModule.registerAsync({
      inject: [ConfigService],
      useFactory: (config: ConfigService) => ({
        root: [config.getOrThrow<string>("VIEW_ROOT")],
        cache: config.get("NODE_ENV") === "production",
      }),
    }),
  ],
})
export class AppModule {}
```

The factory can return the options directly or return a promise.

## Rendering Templates

Inject the LiquidJS `Liquid` class directly. The module exports the same configured instance to consumers:

```typescript
import { Injectable } from "@nestjs/common";
import { Liquid } from "liquidjs";

@Injectable()
export class EmailService {
  constructor(private readonly liquid: Liquid) {}

  async renderWelcomeEmail(
    name: string,
    activationLink: string,
  ): Promise<unknown> {
    return await this.liquid.renderFile("emails/welcome", {
      name,
      activationLink,
    });
  }
}
```

With the default `extname`, `renderFile("emails/welcome")` resolves `views/emails/welcome.liquid`. Use LiquidJS APIs such as `parseAndRender()`, `registerFilter()`, `registerTag()`, and `plugin()` for inline templates and engine customization.

Values rendered with `{{ value }}` are HTML-escaped by default. Use `{{ trustedHtml | raw }}` only when the value is already trusted or sanitized. You can override `outputEscape` through `register()` or `registerAsync()` when rendering a non-HTML output format.

## Migrating from Handlebars

- Replace the `handlebars` dependency with `liquidjs`.
- Rename or rewrite `.hbs` and `.handlebars` templates as `.liquid` templates.
- Replace `ViewService` injection with `Liquid` from `liquidjs`.
- Replace `ViewService.render()` with `Liquid.renderFile()` for files or `Liquid.parseAndRender()` for template strings.
- Templates are resolved by LiquidJS on demand; the module no longer scans and pre-registers template files.
- Interpolated values remain escaped by default. Use LiquidJS's `raw` filter only for trusted HTML.
