Nest Boot 使用 [MikroORM 7.2 原生行级安全](https://mikro-orm.io/docs/row-level-security)，不再提供独立的 RLS 包或自定义数据库驱动。

## 安装

所有 MikroORM 包保持相同版本，要求 **7.2 或以上**。使用数据库对应的官方驱动：

```bash
pnpm add @nest-boot/mikro-orm @nest-boot/request-context @mikro-orm/core @mikro-orm/decorators @mikro-orm/nestjs @mikro-orm/reflection @mikro-orm/postgresql
```

使用 PGlite 时，将 `@mikro-orm/postgresql` 替换为 `@mikro-orm/pglite`，驱动改为 `PgliteDriver`。两种驱动均支持原生的事务级 session 策略。

## 在实体上声明策略

通过 `@Entity({ policies })` 声明策略。有策略时默认启用 RLS。SQL 表达式使用数据库列名；本例使用字符串表达式，确保策略可随元数据缓存完成序列化和还原。

```ts
import { Entity, PrimaryKey, Property } from "@mikro-orm/decorators/legacy";

@Entity({
  policies: [
    {
      name: "document_workspace",
      roles: ["authenticated"],
      using: "workspace_id = nullif(current_setting('app.workspace', true), '')::uuid",
      check: "workspace_id = nullif(current_setting('app.workspace', true), '')::uuid",
    },
  ],
})
export class Document {
  @PrimaryKey({ type: "uuid" })
  id!: string;

  @Property({ type: "uuid", fieldName: "workspace_id" })
  workspaceId!: string;

  @Property({ type: "string" })
  title!: string;
}
```

变量名和 SQL 类型转换必须与 session 配置、字段类型一致。上述表达式在工作区变量缺失或为空时不匹配任何记录。

策略使用 `command: "select" | "insert" | "update" | "delete" | "all"` 和 `type: "permissive" | "restrictive"`。写入检查使用 `check`，不再使用旧的 `withCheck`。限制型策略只收紧已有的允许型策略，不会单独授予访问权。

## 创建数据库角色并授权

原生策略生成**不会**创建角色或执行 GRANT。应用策略迁移前，使用具有数据库管理权限的凭证显式配置：

```sql
create role anonymous nologin;
create role authenticated nologin;
grant anonymous, authenticated to app_connection;

grant usage on schema public to anonymous, authenticated;
grant select, insert, update, delete on document to authenticated;
```

将 `app_connection` 替换为实际连接角色。使用序列生成主键时，还需要授予对应序列的使用权限。匿名角色只能获得业务允许公开的表权限，并配置相应的匿名策略。

表所有者通常绕过 RLS；超级用户和具有 `BYPASSRLS` 的角色即使在 `rowLevelSecurity: "force"` 下也会绕过。请求必须实际切换到受限制的角色，策略才会生效。不要从不可信请求中读取数据库角色名。

## 初始化请求 session

`MikroOrmModuleOptions.session` 是同步工厂函数，返回类型复用原生 `ForkOptions["session"]`。每次创建请求上下文的 EntityManager 分支时，在 Nest Boot 的 `RequestContext` 内执行一次。

```ts
import { PostgreSqlDriver } from "@mikro-orm/postgresql";
import { MikroOrmModule } from "@nest-boot/mikro-orm";
import { headers, RequestContext } from "@nest-boot/request-context";

MikroOrmModule.forRoot({
  driver: PostgreSqlDriver,
  session: () => {
    if (RequestContext.current().type !== "http") return undefined;

    return {
      role: "anonymous",
      variables: {
        "app.workspace": headers().get("x-workspace-id") ?? "",
      },
    };
  },
});
```

`forRootAsync()` 支持相同配置。不配置工厂时保持原生 session 行为；返回 `undefined` 不覆盖父级继承的 session，返回空对象则显式替换。

初始 `app.workspace` 表示选中的工作区，数据库角色保持 `anonymous`。此工厂在**认证中间件之前**运行，不能查询尚未创建的请求 EntityManager。后台任务可以返回自己的 session，而不是读取 HTTP headers。

### 认证完成后

验证身份与工作区访问权后，在请求 EntityManager 上设置认证角色与变量：

```ts
em.setSessionContext({
  role: "authenticated",
  variables: {
    "app.workspace": authorizedWorkspace.id,
    "app.user_id": user.id,
  },
});
```

选择工作区不等于成为成员。示例服务端会在启用工作区范围访问前验证成员关系或工作区 Key 归属；匿名选择仍使用同一个 `app.workspace` 变量。

`setSessionContext()` 会合并变量。过期值需显式覆盖，或先调用 `clearSessionContext()` 再设置完整的新状态。清空会恢复基础连接角色，**不等同于**切换为 `anonymous`。

设置与清空均必须发生在**事务开始之前**，原生 MikroORM 会拒绝在活动事务中修改上下文。

## 查询与事务

默认的 `sessionContext: "transaction"` 使用事务级角色与变量。存在 session 时，显式事务外受支持的 EntityManager 操作会自动包装事务；没有 session 时，不会额外添加这层 RLS 事务包装。

上下文相关 SQL 使用 EntityManager API，包括 `em.execute()`。**`em.getConnection().execute()` 会绕过 EntityManager session**，仅用于经过明确授权的基础设施操作。

带 session 的流式查询需要显式事务。依赖事务级 RLS 时，不要禁用事务。

可选的 `sessionContext: "connection"` 仅支持 PostgreSQL，对连接分配和请求上下文有不同要求。优先使用默认策略，尤其是在 PGlite 或事务级连接池代理下。

## Schema 与迁移

使用官方 `@mikro-orm/migrations`、`Migrator` 和 `Migration`。原生工具管理策略的创建、修改、删除、RLS 开关和迁移快照，不再需要自定义生成器或迁移器。

已有数据库必须在执行 schema diff **之前**，将原有策略名和表达式声明到实体元数据中，否则未声明的策略可能被删除。如果策略仍由外部维护，可显式选择 `schemaGenerator.ignorePolicies: true`，具体限制见官方迁移说明。

示例保留基线迁移中的角色与授权 SQL，并通过普通迁移将策略变量 `app.workspace_id` 切换为 `app.workspace`。

## 从已移除的包迁移

| 原 API                                        | 原生替代                                      |
| --------------------------------------------- | --------------------------------------------- |
| `RowLevelSecurityDriver`                      | `@mikro-orm/postgresql` 的 `PostgreSqlDriver` |
| `PgliteRowLevelSecurityDriver`                | `@mikro-orm/pglite` 的 `PgliteDriver`         |
| `@Policy()`                                   | `@Entity({ policies: [...] })`                |
| `property` / `context` 简写                   | 显式的 `using` / `check` 列名回调             |
| `PolicyMode`、`PolicyCommand`                 | 原生字符串字面量选项                          |
| `RowLevelSecurity.setContext()` / `setRole()` | `em.setSessionContext()`                      |
| 自定义迁移类                                  | 官方 `Migration` / `Migrator`                 |
| `AUTO` / `ENABLED` / `DISABLED`               | 显式原生 session 配置                         |

Auth Service 经服务层授权的持久化操作会在需要时使用独立、无 session 的 EntityManager，不清空调用方的 session，也不连带提交业务层待写入的记录。如果调用方已开启带 RLS 上下文的事务，这类操作会拒绝执行，不会静默脱离事务提交；应先执行 Auth 操作，再开启该业务事务。

## 测试

PGlite 内存数据库适合隔离的策略与请求 session 测试；真实 PostgreSQL 测试用于验证网络驱动与连接行为。集成测试覆盖匿名 session、工作区隔离、读写限制、回滚、结果缓存隔离与原生策略差异。
