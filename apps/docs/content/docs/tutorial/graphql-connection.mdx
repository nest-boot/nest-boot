The `@nest-boot/graphql-connection` module provides cursor-based pagination for GraphQL APIs following the [Relay Connection specification](https://relay.dev/graphql/connections.htm). It integrates with MikroORM to generate type-safe, paginated queries with filtering, sorting, and search capabilities.

## Installation

Requires MikroORM 7.2 or later. Cursor pagination follows the database platform's native null ordering, including when traversing nullable sort fields in either direction.

```bash
npm install @nest-boot/graphql-connection @nest-boot/graphql @nest-boot/database @mikro-orm/core@^7.2.0 @mikro-orm/sql@^7.2.0 @mikro-orm/decorators@^7.2.0
# or
pnpm add @nest-boot/graphql-connection @nest-boot/graphql @nest-boot/database @mikro-orm/core@^7.2.0 @mikro-orm/sql@^7.2.0 @mikro-orm/decorators@^7.2.0
```

## Basic Usage

Import the global module once so Nest can provide `ConnectionManager`:

```typescript
import { GraphQLConnectionModule } from "@nest-boot/graphql-connection";
import { Module } from "@nestjs/common";

@Module({
  imports: [GraphQLConnectionModule],
})
export class AppModule {}
```

### Building Connection Types

```typescript
import { ConnectionBuilder } from "@nest-boot/graphql-connection";
import { User } from "./user.entity";

export const {
  Connection: UserConnection,
  ConnectionArgs: UserConnectionArgs,
  CountArgs: UserCountArgs,
  getCountComplexity: getUserCountComplexity,
} = new ConnectionBuilder(User)
  .addField({ field: "name", type: "string", filterable: true, sortable: true })
  .addField({
    field: "email",
    type: "string",
    filterable: true,
    searchable: true,
  })
  .addField({ field: "createdAt", type: "date", sortable: true })
  .addField({ field: "isActive", type: "boolean", filterable: true })
  .build();
```

### Using in Resolvers

```typescript
import { Args, Query, Resolver } from "@nest-boot/graphql";
import { ConnectionManager } from "@nest-boot/graphql-connection";
import { UserConnection, UserConnectionArgs } from "./user.connection";

@Resolver()
export class UserResolver {
  constructor(private readonly connectionManager: ConnectionManager) {}

  @Query(() => UserConnection)
  async users(@Args() args: UserConnectionArgs) {
    return this.connectionManager.find(UserConnection, args);
  }
}
```

### Use Connection Classes

`ConnectionManager.find` accepts only a connection class generated by
`ConnectionBuilder` or its subclass, not a GraphQL type-name string.
Use concrete classes for resolver and argument types too:

```typescript
import { Args, Query, Resolver } from "@nest-boot/graphql";
import { ConnectionManager } from "@nest-boot/graphql-connection";
import { User } from "./user.entity";
import { UserConnection, UserConnectionArgs } from "./user.connection";

@Resolver(() => User)
export class UserResolver {
  constructor(private readonly connectionManager: ConnectionManager) {}

  @Query(() => UserConnection)
  async users(
    @Args({ type: () => UserConnectionArgs }) args: UserConnectionArgs,
  ) {
    return this.connectionManager.find(UserConnection, args);
  }
}
```

`Args` and `Resolver` are direct Nest re-exports. The string-callback extensions
and named-type lookup helpers have been removed.

## Pagination

Supply exactly one of `first` and `last` with an integer from 1 to 100. Use `after` with `first` or `before` with `last`. Missing, conflicting, or out-of-range paging arguments return `BAD_USER_INPUT`.

If a field returns a generated Connection with a custom pagination contract, set that field's `complexity` explicitly to price its page size and results.

## Filtering

MongoDB-style filter syntax with operators: `$eq`, `$ne`, `$gt`, `$gte`, `$lt`, `$lte`, `$in`, `$nin`, `$and`, `$or`, `$not`, `$fulltext`, `$prefix`, `$contains`, and `$overlap`.

String fields can map full-text filters to a dedicated MikroORM full-text property:

```typescript
import { Entity, Property } from "@mikro-orm/decorators/legacy";
import { SearchableProperty } from "@nest-boot/database";

@Entity()
class Book {
  @Property()
  title!: string;

  @SearchableProperty({ properties: "title", nullable: true })
  searchableTitle!: string | null;
}

export const { Connection: BookConnection } = new ConnectionBuilder(Book)
  .addField({
    field: "title",
    type: "string",
    filterable: true,
    searchable: true,
    fulltext: "searchableTitle",
  })
  .build();
```

With that configuration, `filter: { title: { $fulltext: "你好世界" } }` and `query: "title:你好世界"` both search `searchableTitle`. The shared filter schema uses `operatorTransforms.$fulltext` to automatically apply `@nest-boot/database`'s `tokenizer` after operand validation and before field mapping or replacement callbacks, using the same word boundaries as `SearchableProperty`. Query strings and GraphQL filter inputs, including logical groups, pass through this schema; callers can supply the original text. Ordinary comparisons such as `$eq` keep their original text. Programmatic `args.filter` and `options.where` are native MikroORM conditions; use `filterQuerySchema.parse(...)` for schema-validated and tokenized input.

Custom operator transforms configured through `ConnectionBuilder`'s `filter.operatorTransforms` are preserved. An explicit `$fulltext` transform overrides the default tokenizer; use the same tokenization as the indexed column. Full-text conditions introduced by replacement callbacks retain the text supplied by the callback.

A full-text value containing only whitespace or punctuation remains an empty `$fulltext` condition and matches no records. Regenerate existing search-column values with the same tokenizer when adopting multilingual full-text queries.

### Calendar-date filters

For scalar fields declared with `type: "date"`, structured `filter` values in
`YYYY-MM-DD` format represent a complete day. Full ISO timestamps retain their
exact time. The backend expands dates after validating filters and resolving
field aliases. Callback output targeting these registered date paths follows the
same rule: return a full ISO timestamp when an exact instant is intended.

Send `X-Timezone-Offset: String(new Date().getTimezoneOffset())` from the client.
The value is integer minutes of UTC minus local time (UTC+8 sends `-480`). It is a
fixed offset for the whole request, including historical dates; it does not carry
IANA timezone or daylight-saving rules. Missing headers use UTC (`0`); invalid
values outside `-840` through `840` are rejected.

| Date condition     | Result in the request's fixed offset                             |
| ------------------ | ---------------------------------------------------------------- |
| Bare date or `$eq` | At or after the day's start, before the next day's start         |
| `$ne`              | Exclude that day                                                 |
| `$gte` / `$lt`     | Compare with the day's start                                     |
| `$gt` / `$lte`     | At or after / before the next day's start                        |
| `$between`         | Include both calendar days, excluding the day after the end date |

For example, `{ created_at: { $lte: "2026-09-24" } }` with offset `-480`
becomes `{ createdAt: { $lt: "2026-09-24T16:00:00.000Z" } }` when the field
maps to `createdAt`. This avoids relying on database fractional-second precision.
Date values in `$in` / `$nin` and logical combinations are also supported.
This behavior applies to structured filters, not dates already parsed into
precise instants by the text search syntax.

## Search Query

Human-friendly search syntax with field-specific filters: `field:value`, quoted strings, and negation.

## Standalone Counts

`ConnectionManager.find()` returns one page. To expose a total, get `CountArgs` and `getCountComplexity` from `ConnectionBuilder.build()` and define a separate query. Share the same `query`, `filter`, and server-side scope between the list and count.

```typescript
import { Count, type CountArgsInterface } from "@nest-boot/graphql-connection";
import {
  getUserCountComplexity,
  UserConnection,
  UserCountArgs,
} from "./user.connection";

@Query(() => Count, { complexity: getUserCountComplexity })
async usersCount(
  @Args({ type: () => UserCountArgs }) args: CountArgsInterface<User>,
): Promise<Count> {
  return this.connectionManager.count(UserConnection, args);
}
```

Up to 10,000 matches return `precision: EXACT`. Above that threshold, the query returns `count: 10000` with `precision: AT_LEAST`. Clients can request subsequent pages using only the list query. With rate limiting enabled, the count costs 10 base points plus the cost of applying the filters once.

## Features

- **Relay Compliant** - Follows the Relay Connection specification
- **Type-Safe** - Fully typed with TypeScript generics
- **MikroORM SQL Integration** - Works with MikroORM SQL entities and query builders
- **MongoDB-Style Filtering** - Powerful filter syntax with validation
- **Search Syntax** - Human-friendly search query parsing
- **Cursor-Based Pagination** - Stable pagination with opaque cursors

ID is included as a sort key by default. Declare `.addField({ field: "id", type: "string", sortable: false })` to hide it from public ordering while retaining it as the internal cursor tie-breaker. Programmatic `orderBy.field` uses the decoded entity path, such as `createdAt`; GraphQL clients use the corresponding enum, such as `CREATED_AT`.

When the GraphQL node is a separate view, `new ConnectionBuilder(NodeView, { entity: PersistentEntity })` selects the entity used for database queries. NodeView still defines the GraphQL type name and node fields.
