The `@nest-boot/validator` package provides i18n-aware decorators built on [class-validator](https://github.com/typestack/class-validator). It does not register a Nest module or a global validation pipe for you.

## Installation

```bash
pnpm add @nest-boot/validator @nest-boot/i18n class-validator class-transformer
```

## Usage

Apply the `ValidationPipe` globally in `main.ts`:

```typescript
import { ValidationPipe } from "@nestjs/common";
import { NestFactory } from "@nestjs/core";
import { AppModule } from "./app/app.module";

async function bootstrap() {
  const app = await NestFactory.create(AppModule);

  app.useGlobalPipes(
    new ValidationPipe({
      transform: true,
      forbidUnknownValues: false,
    }),
  );

  await app.listen(process.env.PORT ?? 4000);
}

void bootstrap();
```

### Validating Input Types

Use Nest Boot's decorators alongside the standard `class-validator` decorators. Nest Boot's default messages are resolved through `@nest-boot/i18n` using the `validation` and `property` namespaces.

```typescript
import { Field, InputType } from "@nest-boot/graphql";
import { IsEmail, IsTimezone, Length } from "@nest-boot/validator";
import { IsString } from "class-validator";

@InputType()
export class CreateUserInput {
  @IsString()
  @Length(2, 80)
  @Field(() => String)
  name!: string;

  @IsEmail()
  @Field(() => String)
  email!: string;

  @IsTimezone()
  @Field(() => String)
  timezone!: string;
}
```

The package also exports `ArrayLength`, `IsDate`, `IsDomain`, `IsNumberString`, `IsUrl`, `Min`, `Max`, and comparison decorators such as `IsGreaterThan`. `IsOptional` and `ValidateNested` are re-exported from `class-validator` for convenience.
