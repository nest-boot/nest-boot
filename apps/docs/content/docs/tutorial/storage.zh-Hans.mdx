`@nest-boot/storage` 模块基于 `@nest-boot/s3` 提供的全局 `S3Client`，提供 Laravel 风格的文件操作和 Node.js 风格的文件 I/O。所有路径都相对于可选的 storage root，列表会自动处理分页，并把 S3 prefix 表现为目录。

## 安装

```bash
pnpm add @nest-boot/storage @nest-boot/s3 @aws-sdk/client-s3 @aws-sdk/lib-storage
```

`@nest-boot/s3` 是对等依赖。请在根应用中注册一次 `S3Module` 和 `StorageModule`；两个模块都会全局导出 provider。

## 环境变量配置

直接导入模块时，除 [S3 模块](/docs/tutorial/s3)记录的客户端环境变量外，storage 操作还会读取 `S3_BUCKET`：

```typescript
import { S3Module } from "@nest-boot/s3";
import { StorageModule } from "@nest-boot/storage";
import { Module } from "@nestjs/common";

@Module({
  imports: [S3Module, StorageModule],
})
export class AppModule {}
```

```dotenv
S3_ACCESS_KEY_ID=minio
S3_SECRET_ACCESS_KEY=password
S3_REGION=us-east-1
S3_ENDPOINT_URL=http://localhost:9000
S3_BUCKET=uploads
S3_FORCE_PATH_STYLE=true
```

模块不会读取 `S3_ROOT`。如果 storage 实例需要限制在某个 key prefix 下，请显式配置 root。

## 显式配置

通过 `register()` 选择 bucket 与 key root：

```typescript
StorageModule.register({
  bucket: "uploads",
  root: "tenants/acme",
});
```

传给 `Storage` 的路径仍然相对于 `tenants/acme`，返回的文件和目录路径不会暴露该 root。

需要从其他 provider 获取选项时使用 `registerAsync()`：

```typescript
import { ConfigService } from "@nestjs/config";

StorageModule.registerAsync({
  inject: [ConfigService],
  useFactory: (config: ConfigService) => ({
    bucket: config.getOrThrow("S3_BUCKET"),
    root: config.get("STORAGE_ROOT"),
  }),
});
```

## 文件操作

可以在任意 provider 中注入 `Storage`：

```typescript
import { Storage } from "@nest-boot/storage";
import { Injectable } from "@nestjs/common";

@Injectable()
export class DocumentsService {
  constructor(private readonly storage: Storage) {}

  async publish(): Promise<void> {
    await this.storage.writeFile("documents/report.txt", "ready", {
      ContentType: "text/plain",
    });
    await this.storage.copyFile("documents/report.txt", "archive/report.txt");
    await this.storage.moveFile("archive/report.txt", "published/report.txt");
    await this.storage.deleteFile([
      "documents/report.txt",
      "published/report.txt",
    ]);
  }
}
```

`writeFile`、`copyFile`、`moveFile` 和 `deleteFile` 会在 S3 接受操作后完成，否则抛出 AWS SDK 错误。`copyFile` 以及基于它实现的 `moveFile` 支持最大 5 GB 的源对象；更大的对象会在复制前直接报错。`deleteFile` 同时接受单个路径或路径数组，并按 S3 每批最多 1,000 个对象的限制自动拆分。

## Node.js 风格的文件 I/O

`readFile()` 默认返回 `Buffer`，传入 encoding 后返回字符串。`writeFile()` 接受字符串、array buffer view、iterable 和 async iterable，并替换目标对象：

```typescript
await storage.writeFile("documents/status.txt", "ready", "utf8");

const buffer = await storage.readFile("documents/status.txt");
const text = await storage.readFile("documents/status.txt", "utf8");
```

大文件或渐进生成的内容可以使用流。`createReadStream()` 支持包含边界的 `start` 与 `end` 字节偏移；`createWriteStream()` 使用 AWS managed multipart uploader，并且会等到 S3 完成上传后才触发 `finish`：

```typescript
import { finished } from "node:stream/promises";

const readable = storage.createReadStream("videos/input.mp4", {
  start: 0,
  end: 1023,
});

const writable = storage.createWriteStream("videos/output.mp4", {
  ContentType: "video/mp4",
});
readable.pipe(writable);
await finished(writable);
```

buffer、encoding、AbortSignal 和流的行为参考 [Node.js 文件系统 API](https://nodejs.org/api/fs.html)，同时保留 S3 特有的请求与 multipart 选项。

## 文件与目录列表

```typescript
const entries = await storage.listEntries("documents");
const recursiveEntries = await storage.listEntries("documents", {
  recursive: true,
});
```

`listEntries` 默认返回直接子项，启用 `recursive` 后返回所有后代。每个排序后的条目都包含相对于 storage root 的 `path`，以及值为 `file` 或 `directory` 的 `type`；文件条目还可能包含 `size`、`lastModified` 和 `etag`。S3 没有物理目录，因此目录条目通过对象 key prefix 推导，也会识别空目录 marker 对象。

公开接口有意收敛为 `createReadStream`、`createWriteStream`、`readFile`、`writeFile`、`deleteFile`、`copyFile`、`moveFile` 和 `listEntries`。命名参考 [Laravel 13 Filesystem API](https://laravel.com/framework/docs/13.x/filesystem) 与 Node.js，但不追求与 `node:fs` 完全兼容。
