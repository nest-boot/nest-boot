---
title: "Storage"
description: "通过 S3 兼容对象存储使用 Laravel 风格的文件操作。"
---

`@nest-boot/storage` 模块会创建全局 AWS SDK `S3Client`，并基于它提供 Laravel 风格的文件操作和 Node.js 风格的文件 I/O。所有路径都相对于可选的 storage root，列表会自动处理分页，并把 S3 prefix 表现为目录。

## 安装

```bash
pnpm add @nest-boot/storage @aws-sdk/client-s3 @aws-sdk/lib-storage @aws-sdk/s3-presigned-post @aws-sdk/s3-request-presigner
```

请在根应用中注册一次 `StorageModule`。它会全局导出 `S3Client` 和 `Storage`。

## 环境变量配置

直接导入模块时，会从环境变量读取支持的 `STORAGE_*` 配置：

```typescript
import { StorageModule } from "@nest-boot/storage";
import { Module } from "@nestjs/common";

@Module({
  imports: [StorageModule],
})
export class AppModule {}
```

```dotenv
STORAGE_ACCESS_KEY_ID=minio
STORAGE_SECRET_ACCESS_KEY=password
STORAGE_REGION=us-east-1
STORAGE_ENDPOINT_URL=http://localhost:9000
STORAGE_INTERNAL_ENDPOINT_URL=
STORAGE_PUBLIC_ENDPOINT_URL=
STORAGE_BUCKET=uploads
STORAGE_ROOT_PATH=
STORAGE_FORCE_PATH_STYLE=true
```

如果 storage 实例需要限制在某个 key prefix 下，请设置 `STORAGE_ROOT_PATH`；留空则访问 bucket 根路径。

`STORAGE_ENDPOINT_URL` 是临时 URL 使用的公共 S3 端点；未配置 CDN 覆盖时，直接 URL 也使用它。服务端对象操作需要使用不同的私网端点时设置 `STORAGE_INTERNAL_ENDPOINT_URL`；未设置时会回退到 S3 端点。

需要让 `getUrl()` 返回 CDN 地址时设置 `STORAGE_PUBLIC_ENDPOINT_URL`；它是选填项，未设置时回退到 `STORAGE_ENDPOINT_URL`。临时 URL 仍使用 `STORAGE_ENDPOINT_URL`，以保证 S3 签名有效。

## 显式配置

通过 `register()` 显式配置 S3 客户端、bucket 与 root path：

```typescript
StorageModule.register({
  bucket: "uploads",
  endpointUrl: "https://storage.example.com",
  forcePathStyle: true,
  internalEndpointUrl: "http://minio:9000",
  publicEndpointUrl: "https://cdn.example.com/assets",
  region: "us-east-1",
  accessKeyId: "minio",
  secretAccessKey: "password",
  rootPath: "tenants/acme",
});
```

传给 `Storage` 的路径仍然相对于 `tenants/acme`，返回的文件和目录路径不会暴露该 root。

需要从其他 provider 获取选项时使用 `registerAsync()`：

```typescript
import { ConfigService } from "@nestjs/config";

StorageModule.registerAsync({
  inject: [ConfigService],
  useFactory: (config: ConfigService) => ({
    bucket: config.getOrThrow("STORAGE_BUCKET"),
    endpointUrl: config.get("STORAGE_ENDPOINT_URL"),
    forcePathStyle: config.get("STORAGE_FORCE_PATH_STYLE") === "true",
    internalEndpointUrl: config.get("STORAGE_INTERNAL_ENDPOINT_URL"),
    publicEndpointUrl: config.get("STORAGE_PUBLIC_ENDPOINT_URL"),
    region: config.get("STORAGE_REGION"),
    rootPath: config.get("STORAGE_ROOT_PATH"),
  }),
});
```

## 依赖注入

两个 provider 都会解析为 `StorageModule` 创建的实例，可以在应用的任意位置注入：

```typescript
import { S3Client } from "@aws-sdk/client-s3";
import { Storage } from "@nest-boot/storage";
import { Injectable } from "@nestjs/common";

@Injectable()
export class DocumentsService {
  constructor(
    private readonly s3Client: S3Client,
    private readonly storage: Storage,
  ) {}
}
```

## 文件操作

使用注入的 `Storage` 执行文件操作：

```typescript
import { Storage } from "@nest-boot/storage";
import { Injectable } from "@nestjs/common";

@Injectable()
export class DocumentsService {
  constructor(private readonly storage: Storage) {}

  async publish(): Promise<void> {
    await this.storage.writeFile("documents/report.txt", "ready", {
      ContentType: "text/plain",
    });
    await this.storage.copyFile("documents/report.txt", "archive/report.txt");
    await this.storage.moveFile("archive/report.txt", "published/report.txt");
    await this.storage.deleteFile([
      "documents/report.txt",
      "published/report.txt",
    ]);
  }
}
```

`writeFile`、`copyFile`、`moveFile` 和 `deleteFile` 会在 S3 接受操作后完成，否则抛出 AWS SDK 错误。`copyFile` 以及基于它实现的 `moveFile` 支持最大 5 GB 的源对象；更大的对象会在复制前直接报错。`deleteFile` 同时接受单个路径或路径数组，并按 S3 每批最多 1,000 个对象的限制自动拆分。

## Node.js 风格的文件 I/O

`readFile()` 默认返回 `Buffer`，传入 encoding 后返回字符串。`writeFile()` 接受字符串、array buffer view、iterable 和 async iterable，并替换目标对象：

```typescript
await storage.writeFile("documents/status.txt", "ready", "utf8");

const buffer = await storage.readFile("documents/status.txt");
const text = await storage.readFile("documents/status.txt", "utf8");
```

大文件或渐进生成的内容可以使用流。`createReadStream()` 支持包含边界的 `start` 与 `end` 字节偏移；`createWriteStream()` 使用 AWS managed multipart uploader，并且会等到 S3 完成上传后才触发 `finish`：

```typescript
import { finished } from "node:stream/promises";

const readable = storage.createReadStream("videos/input.mp4", {
  start: 0,
  end: 1023,
});

const writable = storage.createWriteStream("videos/output.mp4", {
  ContentType: "video/mp4",
});
readable.pipe(writable);
await finished(writable);
```

buffer、encoding、AbortSignal 和流的行为参考 [Node.js 文件系统 API](https://nodejs.org/api/fs.html)，同时保留 S3 特有的请求与 multipart 选项。

## 对象 URL

`getUrl()` 使用 S3 客户端解析出的 endpoint 返回 path-style 或 virtual-host-style 直连 URL，适用于调用方已经可以读取的 bucket 或对象：

```typescript
const publicUrl = await storage.getUrl("documents/report.pdf");
```

需要签名读取 URL 时使用 `createTemporaryUrl()`，过期时间以秒为单位：

```typescript
const downloadUrl = await storage.createTemporaryUrl("documents/report.pdf", {
  expiresIn: 300,
  ResponseContentDisposition: 'attachment; filename="report.pdf"',
});
```

`createTemporaryUploadUrl()` 返回 presigned POST URL 和所有必需的表单字段。Storage 会自动把 key 限制在配置的 root 下，并在 POST policy 中约束 bucket 与 key：

```typescript
const upload = await storage.createTemporaryUploadUrl("tmp/report.pdf", {
  conditions: [["content-length-range", 1, 10 * 1024 * 1024]],
  expiresIn: 300,
  fields: { "Content-Type": "application/pdf" },
});
```

## 文件与目录列表

```typescript
const entries = await storage.listEntries("documents");
const recursiveEntries = await storage.listEntries("documents", {
  recursive: true,
});
```

`listEntries` 默认返回直接子项，启用 `recursive` 后返回所有后代。每个排序后的条目都包含相对于 storage root 的 `path`，以及值为 `file` 或 `directory` 的 `type`；文件条目还可能包含 `size`、`lastModified` 和 `etag`。S3 没有物理目录，因此目录条目通过对象 key prefix 推导，也会识别空目录 marker 对象。

文件操作接口包括 `createReadStream`、`createWriteStream`、`readFile`、`writeFile`、`deleteFile`、`copyFile`、`moveFile` 和 `listEntries`；URL 操作由 `getUrl`、`createTemporaryUrl` 与 `createTemporaryUploadUrl` 提供。命名参考 [Laravel 13 Filesystem API](https://laravel.com/framework/docs/13.x/filesystem) 与 Node.js，但不追求与 `node:fs` 完全兼容。
