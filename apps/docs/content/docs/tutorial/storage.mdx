title: "Storage"
description: "Use Laravel-inspired file operations with an S3-compatible object store."
---

The `@nest-boot/storage` module creates a global AWS SDK `S3Client` and provides Laravel-inspired file operations and Node.js-style file I/O on top of it. Paths are relative to an optional storage root, listings are automatically paginated, and S3 prefixes are exposed as directories.

## Installation

```bash
pnpm add @nest-boot/storage @aws-sdk/client-s3 @aws-sdk/lib-storage @aws-sdk/s3-presigned-post @aws-sdk/s3-request-presigner
```

Register `StorageModule` once in the root application. It exposes both `S3Client` and `Storage` globally.

## Environment Configuration

Importing the module directly reads the supported `STORAGE_*` variables from the environment:

```typescript
import { StorageModule } from "@nest-boot/storage";
import { Module } from "@nestjs/common";

@Module({
  imports: [StorageModule],
})
export class AppModule {}
```

```dotenv
STORAGE_ACCESS_KEY_ID=minio
STORAGE_SECRET_ACCESS_KEY=password
STORAGE_REGION=us-east-1
STORAGE_ENDPOINT_URL=http://localhost:9000
STORAGE_INTERNAL_ENDPOINT_URL=
STORAGE_PUBLIC_ENDPOINT_URL=
STORAGE_BUCKET=uploads
STORAGE_ROOT_PATH=
STORAGE_FORCE_PATH_STYLE=true
```

Set `STORAGE_ROOT_PATH` when the storage instance must be limited to a key prefix. Leave it empty to address the bucket root.

`STORAGE_ENDPOINT_URL` is the externally reachable S3 endpoint used for temporary uploads and, without a public endpoint override, direct and temporary download URLs. Set `STORAGE_INTERNAL_ENDPOINT_URL` when server-side object operations should use a different private-network endpoint; otherwise it falls back to the S3 endpoint.

Set `STORAGE_PUBLIC_ENDPOINT_URL` to a public S3-compatible CDN or proxy endpoint for `getUrl()` and `createTemporaryUrl()`. It is optional and falls back to `STORAGE_ENDPOINT_URL`. Because the endpoint hostname participates in the S3 signature, the configured CDN or proxy must forward S3 SigV4 requests without invalidating the signed host.

## Explicit Configuration

Use `register()` to configure the S3 client, bucket, and root path explicitly:

```typescript
StorageModule.register({
  bucket: "uploads",
  endpointUrl: "https://storage.example.com",
  forcePathStyle: true,
  internalEndpointUrl: "http://minio:9000",
  publicEndpointUrl: "https://cdn.example.com/assets",
  region: "us-east-1",
  accessKeyId: "minio",
  secretAccessKey: "password",
  rootPath: "tenants/acme",
});
```

All paths passed to `Storage` remain relative to `tenants/acme`. The returned file and directory paths do not expose that root.

Use `registerAsync()` when another provider supplies the options:

```typescript
import { ConfigService } from "@nestjs/config";

StorageModule.registerAsync({
  inject: [ConfigService],
  useFactory: (config: ConfigService) => ({
    bucket: config.getOrThrow("STORAGE_BUCKET"),
    endpointUrl: config.get("STORAGE_ENDPOINT_URL"),
    forcePathStyle: config.get("STORAGE_FORCE_PATH_STYLE") === "true",
    internalEndpointUrl: config.get("STORAGE_INTERNAL_ENDPOINT_URL"),
    publicEndpointUrl: config.get("STORAGE_PUBLIC_ENDPOINT_URL"),
    region: config.get("STORAGE_REGION"),
    rootPath: config.get("STORAGE_ROOT_PATH"),
  }),
});
```

## Dependency Injection

Both providers resolve to the instances created by `StorageModule` and can be injected anywhere in the application:

```typescript
import { S3Client } from "@aws-sdk/client-s3";
import { Storage } from "@nest-boot/storage";
import { Injectable } from "@nestjs/common";

@Injectable()
export class DocumentsService {
  constructor(
    private readonly s3Client: S3Client,
    private readonly storage: Storage,
  ) {}
}
```

## File Operations

Use the injected `Storage` for file operations:

```typescript
import { Storage } from "@nest-boot/storage";
import { Injectable } from "@nestjs/common";

@Injectable()
export class DocumentsService {
  constructor(private readonly storage: Storage) {}

  async publish(): Promise<void> {
    await this.storage.writeFile("documents/report.txt", "ready", {
      ContentType: "text/plain",
    });
    await this.storage.copyFile("documents/report.txt", "archive/report.txt");
    await this.storage.moveFile("archive/report.txt", "published/report.txt");
    await this.storage.deleteFile([
      "documents/report.txt",
      "published/report.txt",
    ]);
  }
}
```

`writeFile`, `copyFile`, `moveFile`, and `deleteFile` resolve when S3 accepts the operation and reject with the AWS SDK error otherwise. `copyFile`, and therefore `moveFile`, accepts source objects up to 5 GB; larger objects are rejected before copying. `deleteFile` accepts one path or an array and automatically splits batches at the S3 limit of 1,000 objects.

## Node.js-style File I/O

`readFile()` returns a `Buffer` by default, or a string when an encoding is provided. `writeFile()` accepts strings, array buffer views, iterables, and async iterables, and replaces the destination object:

```typescript
await storage.writeFile("documents/status.txt", "ready", "utf8");

const buffer = await storage.readFile("documents/status.txt");
const text = await storage.readFile("documents/status.txt", "utf8");
```

Use streams for large or progressively produced objects. `createReadStream()` supports inclusive `start` and `end` byte offsets. `createWriteStream()` uses the AWS managed multipart uploader, and its `finish` event is delayed until S3 completes the upload:

```typescript
import { finished } from "node:stream/promises";

const readable = storage.createReadStream("videos/input.mp4", {
  start: 0,
  end: 1023,
});

const writable = storage.createWriteStream("videos/output.mp4", {
  ContentType: "video/mp4",
});
readable.pipe(writable);
await finished(writable);
```

The buffering, encoding, abort signal, and stream behavior follows the core shape of the [Node.js file system API](https://nodejs.org/api/fs.html), while S3-specific request and multipart options remain available.

## Object URLs

`getUrl()` returns a direct path-style or virtual-host-style URL using the S3 client's resolved endpoint. It is appropriate when the bucket or object is already readable by the caller:

```typescript
const publicUrl = await storage.getUrl("documents/report.pdf");
```

Use `createTemporaryUrl()` for a signed read URL. The expiration is expressed in seconds:

```typescript
const downloadUrl = await storage.createTemporaryUrl("documents/report.pdf", {
  expiresIn: 300,
  ResponseContentDisposition: 'attachment; filename="report.pdf"',
});
```

`createTemporaryUploadUrl()` returns a presigned POST URL and all required form fields. Storage automatically scopes the key to its configured root and enforces the selected bucket and key in the POST policy:

```typescript
const upload = await storage.createTemporaryUploadUrl("tmp/report.pdf", {
  conditions: [["content-length-range", 1, 10 * 1024 * 1024]],
  expiresIn: 300,
  fields: { "Content-Type": "application/pdf" },
});
```

## File and Directory Listings

```typescript
const entries = await storage.listEntries("documents");
const recursiveEntries = await storage.listEntries("documents", {
  recursive: true,
});
```

`listEntries` returns immediate children by default and every descendant when `recursive` is enabled. Each sorted entry contains a root-relative `path` and a `type` of `file` or `directory`; file entries can also contain `size`, `lastModified`, and `etag`. Because S3 has no physical directories, directory entries are derived from object key prefixes, including empty directory marker objects.

The file operation surface consists of `createReadStream`, `createWriteStream`, `readFile`, `writeFile`, `deleteFile`, `copyFile`, `moveFile`, and `listEntries`. URL operations are provided by `getUrl`, `createTemporaryUrl`, and `createTemporaryUploadUrl`. The API draws on the [Laravel 13 filesystem API](https://laravel.com/framework/docs/13.x/filesystem) and Node.js naming without attempting complete `node:fs` compatibility.
