---
title: "File Upload"
description: "Handle file uploads with S3-compatible storage, MIME type validation, and file size limits."
---

The `@nest-boot/file-upload` module creates constrained presigned POST uploads for S3-compatible storage, exposes them through GraphQL, supports direct server-side uploads, and copies accepted temporary objects to dated permanent keys.

## Installation

```bash
pnpm add @nest-boot/file-upload @nest-boot/storage @aws-sdk/client-s3 @aws-sdk/lib-storage @aws-sdk/s3-presigned-post @aws-sdk/s3-request-presigner
```

`@nest-boot/storage` is a peer dependency and must be registered once in the application. `FileUploadService` consumes the global `Storage` service and does not access `S3Client` directly.

## Module Registration

```typescript
import { FileUploadModule } from "@nest-boot/file-upload";
import { StorageModule } from "@nest-boot/storage";
import { Module } from "@nestjs/common";
import { ConfigService } from "@nestjs/config";

const FileUploadDynamicModule = FileUploadModule.registerAsync({
  inject: [ConfigService],
  useFactory: (configService: ConfigService) => ({
    url: configService.get("FILE_UPLOAD_URL"),
    expires: 3600,
    limits: [
      {
        fileSize: 10 * 1024 * 1024,
        mimeTypes: ["image/*", "application/pdf"],
      },
    ],
  }),
});

@Module({
  imports: [StorageModule, FileUploadDynamicModule],
})
export class AppModule {}
```

The static `StorageModule` reads `S3_ENDPOINT_URL`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`, `S3_REGION`, `S3_FORCE_PATH_STYLE`, and `S3_BUCKET`. File upload options no longer repeat the bucket or client. See the [Storage tutorial](/docs/tutorial/storage) for explicit and asynchronous storage configuration.

### Configuration Options

| Option    | Description                                                                                  |
| --------- | -------------------------------------------------------------------------------------------- |
| `url`     | Optional public prefix that replaces the origin/path of generated presigned POST URLs        |
| `expires` | Presigned POST lifetime in seconds; defaults to `3600`                                       |
| `limits`  | Accepted `{ fileSize, mimeTypes }` combinations; MIME patterns use micromatch glob semantics |

## Usage

### Creating Presigned Uploads

`FileUploadModule` registers a `createFileUploads` GraphQL mutation. It accepts an array of names, byte sizes, and MIME types, validates each item against `limits`, and returns a presigned POST URL plus the required form fields:

```graphql
mutation CreateFileUploads($input: [FileUploadInput!]!) {
  createFileUploads(input: $input) {
    url
    fields {
      name
      value
    }
  }
}
```

The client must submit every returned field, the file body, and the same `Content-Type` to the returned URL. Generated temporary keys use the `tmp/` prefix.

### Persisting Temporary Objects

After the client upload succeeds, use `persist()` to copy the temporary object to `files/YYYY/MM/DD/...`:

```typescript
import { FileUploadService } from "@nest-boot/file-upload";
import { Injectable } from "@nestjs/common";

@Injectable()
export class FileService {
  constructor(private readonly fileUploadService: FileUploadService) {}

  async persistFile(tempFileUrl: string): Promise<string> {
    return await this.fileUploadService.persist(tempFileUrl);
  }
}
```

`persist()` returns only the permanent object URL. Size and MIME validation happens when `create()` creates the presigned upload, not during `persist()`. The copy operation does not delete the temporary object.

### Direct Server-Side Uploads

Use `upload()` when the server already has the file data. Pass `true` as the third argument to copy the result to permanent storage immediately:

```typescript
const url = await fileUploadService.upload(
  pdfBuffer,
  { "Content-Type": "application/pdf" },
  true,
);
```

## Best Practices

1. **Strict MIME Types** — Only allow the MIME types your application actually needs.

2. **Reasonable Size Limits** — Define one or more `limits` entries that pair a maximum byte size with MIME glob patterns.

3. **Temporary Object Cleanup** — `persist()` copies objects but does not delete the `tmp/` source; configure an S3 lifecycle rule for temporary keys.
