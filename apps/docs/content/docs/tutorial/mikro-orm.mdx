The `@nest-boot/mikro-orm` module wraps [`@mikro-orm/nestjs`](https://mikro-orm.io/docs/usage-with-nestjs) with automatic environment-based configuration and request context integration for per-request entity manager forking. Companion modules provide [encrypted properties](#encrypted-properties) and [hashed properties](#hashed-properties).

## Installation

```bash
pnpm add @nest-boot/mikro-orm @mikro-orm/core @mikro-orm/nestjs @mikro-orm/reflection @mikro-orm/migrations

# Install the driver matching DATABASE_URL
pnpm add @mikro-orm/postgresql
# or: pnpm add @mikro-orm/pglite
```

## Module Registration

### Basic Registration

```typescript
import { PostgreSqlDriver } from "@mikro-orm/postgresql";
import { MikroOrmModule } from "@nest-boot/mikro-orm";

@Global()
@Module({
  imports: [MikroOrmModule.forRoot({ driver: PostgreSqlDriver })],
})
export class CommonModule {}
```

The explicit driver lets MikroORM 7 register the driver-specific `EntityManager`
for dependency injection. Other connection options are optional: the module
auto-loads them with `loadConfigFromEnv()`. It reads `DATABASE_URL` and parses
the URL into structured MikroORM options instead of passing the URL to a
database client. PostgreSQL accepts its documented `postgresql:` and
`postgres:` URI forms. PGlite accepts `file:` for persistent storage and
`memory:` for an in-memory database. Other protocol names and driver-specific
compatibility forms are rejected. Use an absolute URL such as
`file:///var/lib/app/pgdata` for persistent PGlite, or `memory://` for an
ephemeral database. An absent `DATABASE_URL` remains unconfigured instead of
silently falling back to ephemeral storage.

PostgreSQL TLS file parameters use `sslrootcert`, `sslcert`, and `sslkey`; the supported `sslmode` values are `disable`, `require`, `verify-ca`, and `verify-full`. Modes that require retrying with a plaintext connection are rejected because a single structured driver configuration cannot preserve that fallback behavior.

An explicit `clientUrl` or host-style connection target such as `host` or `dbName` takes full precedence and prevents ambient `DATABASE_URL` values from being merged into that connection. Supplemental options such as `driver`, `schema`, `pool`, or `debug` continue to augment automatic environment configuration.

The default config discovers runtime entities from `dist/**/*.entity.js`, TypeScript entities from `src/**/*.entity.ts`, uses `TsMorphMetadataProvider`, enables MikroORM DataLoaders, and stores migrations and seeders under `src/database` (or `dist/database` after build).

Metadata caching is disabled by default (`metadataCache: { enabled: false }`) for both module registration and CLI configuration loaded through `loadConfigFromEnv()`. Entity metadata is rediscovered on each ORM initialization, which may increase startup time, but not on each request. Query result caching is unaffected. Set `metadataCache: { enabled: true }` to opt in; setting only a cache directory or formatting options does not enable it.

MikroORM 7.2.0's JSON metadata cache does not fully preserve policy callbacks. Keep caching disabled when entities use functions for `policies.using` or `policies.check`.

### Async Registration

```typescript
import { loadConfigFromEnv, MikroOrmModule } from "@nest-boot/mikro-orm";
import { PostgreSqlDriver } from "@mikro-orm/postgresql";

@Module({
  imports: [
    MikroOrmModule.forRootAsync({
      driverHint: PostgreSqlDriver,
      useFactory: async () => ({
        ...(await loadConfigFromEnv()),
        debug: true,
      }),
    }),
  ],
})
export class CommonModule {}
```

### CLI Configuration

For MikroORM CLI (migrations, schema generation), create a `mikro-orm.config.ts`:

```typescript
import { existsSync } from "node:fs";
import { loadEnvFile } from "node:process";

import { loadConfigFromEnv } from "@nest-boot/mikro-orm";

if (existsSync(".env")) {
  loadEnvFile();
}

export default loadConfigFromEnv();
```

## Request-Scoped Entity Manager

The module automatically forks the entity manager for each request via `RequestContext`, ensuring proper isolation. You can inject `EntityManager` anywhere:

```typescript
import { EntityManager } from "@mikro-orm/postgresql";
import { Injectable } from "@nestjs/common";

@Injectable()
export class UserService {
  constructor(private readonly em: EntityManager) {}

  async findAll() {
    return this.em.findAll(User);
  }
}
```

### Database session factory

Set `session: () => ({ role: "anonymous", variables: { "app.workspace": "..." } })`
to initialize the native session on each request EntityManager. The synchronous
callback returns `ForkOptions["session"]`, runs inside `RequestContext` before
authentication, and is supported by both `forRoot()` and `forRootAsync()`.
The default is no factory. Applications are responsible for provisioning database
roles and updating the session after authentication, before starting transactions.

## EntityService

`EntityService` is a generic CRUD base class with DataLoader batching for automatic N+1 prevention:

```typescript
import { EntityManager, FilterQuery } from "@mikro-orm/postgresql";
import { EntityService } from "@nest-boot/mikro-orm";
import { Injectable } from "@nestjs/common";

import { User } from "./user.entity.js";

@Injectable()
export class UserService extends EntityService<User> {
  constructor(protected readonly em: EntityManager) {
    super(User, em);
  }
}
```

### Available Methods

| Method                                | Description                                                            |
| ------------------------------------- | ---------------------------------------------------------------------- |
| `create(data)`                        | Create and persist a new entity                                        |
| `findOne(idOrEntity)`                 | Find by ID, entity reference, or filter query (batched via DataLoader) |
| `findOneOrFail(idOrEntity)`           | Same as `findOne` but throws `NotFoundException`                       |
| `findAll(where, options?)`            | Find all entities matching a filter                                    |
| `count(where, options?)`              | Count matching entities                                                |
| `update(idOrEntity, data)`            | Update an entity                                                       |
| `remove(idOrEntity, softDelete?)`     | Remove an entity (supports soft-delete)                                |
| `chunkById(where, options, callback)` | Iterate entities in chunks for batch processing                        |

### Soft Delete

`EntityService` supports soft delete when configured with a `softDeleteKey`:

```typescript
@Injectable()
export class FileService extends EntityService<File> {
  constructor(protected readonly em: EntityManager) {
    super(File, em, { softDeleteKey: "deletedAt" });
  }
}

// Soft delete (sets deletedAt = new Date())
await this.fileService.remove(fileId);

// Hard delete
await this.fileService.remove(fileId, false);
```

### Chunk Processing

Process large datasets in batches:

```typescript
await this.userService.chunkById(
  { isActive: true },
  { limit: 100 },
  async (users) => {
    for (const user of users) {
      await this.sendEmail(user);
    }
  },
);
```

## Encrypted Properties

The `@nest-boot/mikro-orm-crypt` module provides the `@EncryptedProperty()` decorator for transparent field encryption using the `@nest-boot/crypt` module:

```bash
pnpm add @nest-boot/mikro-orm-crypt @nest-boot/crypt
```

```typescript
import { Entity, PrimaryKey, t } from "@mikro-orm/postgresql";
import { EncryptedProperty } from "@nest-boot/mikro-orm-crypt";

@Entity()
export class CloudProviderAccount {
  @PrimaryKey({ type: t.bigint })
  id!: string;

  @EncryptedProperty()
  apiKey!: string;

  @EncryptedProperty()
  apiSecret!: string;
}
```

Values are automatically encrypted on write and decrypted on read. Requires `CryptModule` to be registered:

```typescript
import { CryptModule } from "@nest-boot/crypt";

const CryptDynamicModule = CryptModule.registerAsync({
  inject: [ConfigService],
  useFactory: (configService: ConfigService) => ({
    secret: configService.getOrThrow("CRYPT_SECRET"),
  }),
});
```

`CryptModule` validates that its secret is at least 32 characters and has sufficient entropy. `@EncryptedProperty()` marks the column hidden and lazy by default and encrypts string values before create and update operations.

## Hashed Properties

The `@nest-boot/mikro-orm-hash` module provides the `@HashedProperty()` decorator for transparent field hashing using the `@nest-boot/hash` module:

```bash
pnpm add @nest-boot/mikro-orm-hash @nest-boot/hash
```

```typescript
import { Entity, PrimaryKey, t } from "@mikro-orm/postgresql";
import { HashedProperty } from "@nest-boot/mikro-orm-hash";

@Entity()
export class User {
  @PrimaryKey({ type: t.bigint })
  id!: string;

  @HashedProperty()
  password!: string;
}
```

Values are automatically hashed before create and update operations. The decorator marks the column hidden and lazy by default and does not hash an existing Argon2 value again. `HashModule` must be initialized before entity hooks run.

## Best Practices

1. **Environment Config** — Use `loadConfigFromEnv()` for both runtime and CLI configuration to keep them in sync.

2. **EntityService as Base** — Extend `EntityService` for all domain services to get CRUD + DataLoader batching out of the box.

3. **Soft Delete** — Configure `softDeleteKey` in `EntityService` for entities that support soft delete.
