`@nest-boot/graphql-connection` 模块提供遵循 [Relay 连接规范](https://relay.dev/graphql/connections.htm) 的游标分页。集成 MikroORM，生成类型安全的分页查询，支持过滤、排序和搜索。

## 安装

需要 MikroORM 7.2 或更高版本。游标分页遵循数据库平台原生的空值排序规则，可空字段的正向和反向遍历均适用。

```bash
npm install @nest-boot/graphql-connection @nest-boot/graphql @mikro-orm/core@^7.2.0 @mikro-orm/sql@^7.2.0
# 或
pnpm add @nest-boot/graphql-connection @nest-boot/graphql @mikro-orm/core@^7.2.0 @mikro-orm/sql@^7.2.0
```

## 基本用法

先导入一次全局模块，让 Nest 提供 `ConnectionManager`：

```typescript
import { GraphQLConnectionModule } from "@nest-boot/graphql-connection";
import { Module } from "@nestjs/common";

@Module({
  imports: [GraphQLConnectionModule],
})
export class AppModule {}
```

### 构建 Connection 类型

```typescript
import { ConnectionBuilder } from "@nest-boot/graphql-connection";
import { User } from "./user.entity";

export const {
  Connection: UserConnection,
  ConnectionArgs: UserConnectionArgs,
} = new ConnectionBuilder(User)
  .addField({ field: "name", type: "string", filterable: true, sortable: true })
  .addField({
    field: "email",
    type: "string",
    filterable: true,
    searchable: true,
  })
  .build();
```

### 在 Resolver 中查询

```typescript
import { ConnectionManager } from "@nest-boot/graphql-connection";
import { Args, Info, Query, Resolver } from "@nest-boot/graphql";
import type { GraphQLResolveInfo } from "graphql";

import { UserConnection, UserConnectionArgs } from "./user.connection";

@Resolver()
export class UserResolver {
  constructor(private readonly connectionManager: ConnectionManager) {}

  @Query(() => UserConnection)
  async users(
    @Args() args: UserConnectionArgs,
    @Info() info: GraphQLResolveInfo,
  ) {
    return await this.connectionManager.find(UserConnection, args, { info });
  }
}
```

传入 `@Info()` 后，只有查询选择了 `totalCount` 或 `totalCountRelation`，`ConnectionManager` 才会执行计数查询。

### 使用连接类

`ConnectionManager.find` 只接收 `ConnectionBuilder` 生成的连接类或其子类，
不再接收 GraphQL 类型名称字符串。参数和 Resolver 也使用具体类：

```typescript
import { Args, Query, Resolver } from "@nest-boot/graphql";
import { ConnectionManager } from "@nest-boot/graphql-connection";
import { User } from "./user.entity";
import { UserConnection, UserConnectionArgs } from "./user.connection";

@Resolver(() => User)
export class UserResolver {
  constructor(private readonly connectionManager: ConnectionManager) {}

  @Query(() => UserConnection)
  async users(
    @Args({ type: () => UserConnectionArgs }) args: UserConnectionArgs,
  ) {
    return this.connectionManager.find(UserConnection, args);
  }
}
```

`Args` 和 `Resolver` 直接导出 Nest 原生装饰器，不再提供字符串回调增强或具名类型查找。

## 分页

同时支持正向的 `first`/`after` 和反向的 `last`/`before` 游标分页。

## 过滤

支持 MongoDB 风格过滤操作符：`$eq`、`$ne`、`$gt`、`$gte`、`$lt`、`$lte`、`$in`、`$nin`、`$and`、`$or`、`$not`、`$fulltext`、`$prefix`、`$contains` 和 `$overlap`。

字符串字段可以把全文检索映射到专门的 MikroORM 全文检索属性：

```typescript
import { Entity, Index, Property } from "@mikro-orm/core";
import { FullTextType } from "@mikro-orm/postgresql";

@Entity()
class Book {
  @Property()
  title!: string;

  @Index({ type: "fulltext" })
  @Property({ type: FullTextType, onUpdate: (book) => book.title })
  searchableTitle!: string;
}

export const { Connection: BookConnection } = new ConnectionBuilder(Book)
  .addField({
    field: "title",
    type: "string",
    filterable: true,
    searchable: true,
    fulltext: "searchableTitle",
  })
  .build();
```

这样配置后，`filter: { title: { $fulltext: "nest" } }` 和 `query: "title:nest"` 都会查询 `searchableTitle`；`$eq` 等普通操作符仍然查询 `title`。

### 按天筛选日期

对于声明为 `type: "date"` 的非数组字段，结构化 `filter` 中的 `YYYY-MM-DD`
表示一整天；完整 ISO 时间戳保持精确时间。后端先校验筛选条件、解析字段别名，
再展开日期边界。自定义替换回调输出到这些已登记的日期路径时，也遵循同一规则；
需要精确时刻时，应返回完整 ISO 时间戳。

前端通过 `X-Timezone-Offset: String(new Date().getTimezoneOffset())` 传递偏移。
单位为分钟，含义为 UTC 减本地时间，例如 UTC+8 传 `-480`。整个请求都使用该固定偏移，
包括历史日期，不携带 IANA 时区或夏令时规则。缺少请求头时使用 UTC（`0`），
超出 `-840` 到 `840` 或非整数的值会被拒绝。

| 日期条件       | 按请求中的固定偏移转换             |
| -------------- | ---------------------------------- |
| 裸日期或 `$eq` | 大于等于当天开始，且小于次日开始   |
| `$ne`          | 排除这一天                         |
| `$gte` / `$lt` | 与当天开始比较                     |
| `$gt` / `$lte` | 大于等于／小于次日开始             |
| `$between`     | 包含起止两天，小于结束日的次日开始 |

例如偏移为 `-480` 时，`{ created_at: { $lte: "2026-09-24" } }` 会转换为
`{ createdAt: { $lt: "2026-09-24T16:00:00.000Z" } }`（该字段映射为 `createdAt`）。
使用次日开始作为排他上界，可以避免数据库小数秒精度造成的遗漏。
同时支持 `$in`、`$nin` 中的日期和逻辑组合。此规则适用于结构化筛选，
不改变文本搜索语法已解析为精确时刻的日期值。

## 搜索查询

支持面向用户的字段搜索语法，包括 `field:value`、带引号的字符串和否定条件。

## 有界总数

Connection 同时提供 `totalCount` 和 `totalCountRelation`。不超过 10,000 条时返回精确数量和 `EQ`；超过 10,000 条时返回 `totalCount: 10000` 和 `totalCountRelation: GTE`。

计数由数据库侧最多处理 10,001 条匹配记录的有界查询完成。Resolver 按上面的示例传入 `@Info()` 后，如果两个计数字段都没有被选择，就不会执行这条查询。

## 特性

- **Relay 兼容** - 遵循 Relay 连接规范
- **类型安全** - 使用 TypeScript 泛型完全类型化
- **MikroORM SQL 集成** - 与 MikroORM SQL 实体和 QueryBuilder 配合
- **MongoDB 风格过滤** - 强大的过滤语法和验证
- **搜索语法** - 人性化的搜索查询解析
- **游标分页** - 使用不透明游标进行稳定分页
