## Global Guard

Register the configured module's `AuthGuard` globally. It accepts a valid Cookie
session or API key and evaluates route permissions with the same guard.

```typescript
import { AuthGuard } from "@nest-boot/auth";
import { APP_GUARD } from "@nestjs/core";

@Global()
@Module({
  imports: [AuthDynamicModule],
  providers: [{ provide: APP_GUARD, useExisting: AuthGuard }],
})
export class CommonModule {}
```

Use `@Public()` for routes that do not require authentication. If a public route
also declares `@Can`, its permission is still evaluated.

```typescript
@Public()
@Query(() => String)
health(): string {
  return "ok";
}
```

## Build Abilities

Configure separate user and workspace abilities. Each callback runs at most
once per request and its result is cached in `RequestContext`. Returning `null`
causes that authorization scope to fail.

```typescript
import { AuthModule, PermissionAbilityBuilder } from "@nest-boot/auth";
import { RequestContext } from "@nest-boot/request-context";

AuthModule.forRoot({
  // ...
  buildWorkspaceAbility: () => {
    const { can, build } = new PermissionAbilityBuilder();
    can("read", Post);
    return build();
  },
  buildUserAbility: () => {
    const user = RequestContext.get(User);
    if (!user) return null;

    const { can, build } = new PermissionAbilityBuilder();
    can("read", Post);
    can("update", Post, { authorId: user.id });
    return build();
  },
});
```

## Protect Routes

`@Can` uses the workspace scope by default. Pass `{ scope: "user" }` for
personal or application-level operations.

```typescript
@Can("read", Post)
@Query(() => [Post])
posts() {
  return this.postService.findAll();
}

@Can("read", User, { scope: "user" })
@Query(() => User)
me(@CurrentUser() user: User) {
  return user;
}
```

Use a subject factory when authorization depends on a concrete object. The
factory receives the controller or resolver instance first, followed by its
decorated method parameters.

```typescript
@Can("update", (self: PostResolver, id: string) =>
  self.postService.findOneOrFail({ id }),
)
@Mutation(() => Post)
updatePost(@Args("id") id: string) {
  return this.postService.update(id);
}
```

Workspace API keys can pass only workspace checks. User API keys can pass user
checks and, with a live membership, workspace checks. API-key permissions are
intersected with the corresponding ability.

## Lower-Level Checks

After route-level `@Can` prepares an ability, lower-level code can use `can()`
or `getPermissionAbility()`. Both default to workspace scope and accept the same
explicit user scope.

```typescript
if (!can("update", post)) {
  throw new ForbiddenException();
}

can("read", user, { scope: "user" });
getPermissionAbility("user");
```

Both helpers throw `ForbiddenException` if the route did not prepare the
requested ability.
