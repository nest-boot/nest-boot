## 模块选项

通过 `forRoot()` 或 `forRootAsync()` 注册 `AuthModule`。模块仅开放经过明确允许的
Better Auth 选项，避免上游升级无意中扩大 Nest Boot 的公开 API。
`AuthModuleOptions` 不允许注入 Better Auth 插件。

主要选项包括：

- **`entities`** — 每个认证模型对应的应用实体类；
- **`emailAndPassword.enabled`** — 启用邮箱密码认证，默认为 `true`；
- **`emailAndPassword.requireEmailVerification`** — 登录前要求验证邮箱，默认为 `true`；
- **`emailAndPassword.password`** — 覆盖密码哈希，默认使用 `HashService`；
- **`emailAndPassword.sendResetPassword`** — 覆盖密码重置邮件发送逻辑；
- **`emailVerification.sendVerificationEmail`** — 覆盖验证邮件发送逻辑；
- **`user.changeEmail.enabled`** — 启用两阶段邮箱修改；
- **`workspace.sendInvitationEmail`** — 发送已持久化的工作区邀请；
- **`buildUserAbility`** 与 **`buildWorkspaceAbility`** — 构建请求权限 Ability；
- **`onAuthenticated`** — 会话解析后补充应用上下文；
- **`middleware`** — 控制认证中间件的注册和路由范围；
- **`basePath`** — 修改默认的 `/api/auth/` 认证端点路径；
- **`trustedOrigins`** — 配置允许的浏览器来源。

## 环境变量

传给 `forRoot()` 或 `forRootAsync()` 的选项会与环境变量默认值合并。认证提供方的
环境变量开关可以覆盖对应的嵌套 provider 设置。

### 通用

| 变量                   | 用途                                                                                  | 默认值                     |
| ---------------------- | ------------------------------------------------------------------------------------- | -------------------------- |
| `AUTH_SECRET`          | 用于签名和加密认证数据的密钥。未设置时回退到 `APP_SECRET`；应至少包含 32 个高熵字符。 | 必填                       |
| `HASH_SECRET`          | `HashModule` 使用的 pepper。未设置时回退到 `APP_SECRET`；应至少包含 32 个高熵字符。   | `APP_SECRET` 未设置时必填  |
| `APP_SECRET`           | auth 或 hash 专用密钥缺失时使用的共享备用密钥。                                       | `AUTH_SECRET` 未设置时必填 |
| `APP_NAME`             | 传给 Better Auth 的应用名称。                                                         | 未设置                     |
| `AUTH_URL`             | 公开的认证基础 URL，未设置时回退到 `APP_URL`。                                        | 未设置                     |
| `APP_URL`              | 应用公开 URL，同时作为 `AUTH_URL` 的备用值。                                          | 未设置                     |
| `AUTH_DISABLE_SIGN_UP` | 禁止所有已配置认证方式的新用户注册，但不影响已有用户登录。                            | 允许注册                   |
| `API_KEY_PREFIX`       | 创建 API Key 时使用的前缀。                                                           | `sk-`                      |

### Email

| 变量                              | 用途                                     | 默认值   |
| --------------------------------- | ---------------------------------------- | -------- |
| `AUTH_EMAIL_ENABLED`              | 除非设为 `false`，否则启用邮箱密码认证。 | 启用     |
| `AUTH_EMAIL_REQUIRE_VERIFICATION` | 除非设为 `false`，否则要求验证邮箱。     | 要求验证 |
| `AUTH_EMAIL_DISABLE_SIGN_UP`      | 设为 `true` 时禁止新的邮箱密码注册。     | 允许注册 |

### Google 与 GitHub

Google 与 GitHub 只有在对应的 `*_ENABLED` 为 `true` 时才会启用。启用后必须同时提供
client ID 与 client secret。

| 变量                          | 用途                                 |
| ----------------------------- | ------------------------------------ |
| `AUTH_GOOGLE_ENABLED`         | 启用 Google 认证。                   |
| `AUTH_GOOGLE_CLIENT_ID`       | Google OAuth 客户端 ID。             |
| `AUTH_GOOGLE_CLIENT_SECRET`   | Google OAuth 客户端密钥。            |
| `AUTH_GOOGLE_DISABLE_SIGN_UP` | 禁止新 Google 用户注册，但保留登录。 |
| `AUTH_GITHUB_ENABLED`         | 启用 GitHub 认证。                   |
| `AUTH_GITHUB_CLIENT_ID`       | GitHub OAuth 客户端 ID。             |
| `AUTH_GITHUB_CLIENT_SECRET`   | GitHub OAuth 客户端密钥。            |
| `AUTH_GITHUB_DISABLE_SIGN_UP` | 禁止新 GitHub 用户注册，但保留登录。 |

### OIDC

Generic OIDC 默认关闭。设置 `AUTH_OIDC_ENABLED=true` 后，`AuthModule` 会注册一个
`providerId: "oidc"` 的内部 `genericOAuth` provider。

| 变量                        | 用途                                                                                                               | 默认值                 |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------ | ---------------------- |
| `AUTH_OIDC_ENABLED`         | 启用 generic OIDC provider。                                                                                       | 禁用                   |
| `AUTH_OIDC_CLIENT_ID`       | OIDC 客户端 ID。                                                                                                   | 启用时必填             |
| `AUTH_OIDC_CLIENT_SECRET`   | OIDC 客户端密钥。                                                                                                  | 启用时必填             |
| `AUTH_OIDC_DISCOVERY_URL`   | OIDC discovery 文档 URL。                                                                                          | 启用时必填             |
| `AUTH_OIDC_PROMPT`          | 可选 prompt：`none`、`login`、`create`、`consent`、`select_account`、`select_account consent` 或 `login consent`。 | 未设置                 |
| `AUTH_OIDC_SCOPES`          | 逗号分隔的 scope；空白和空项会被忽略。                                                                             | `openid,profile,email` |
| `AUTH_OIDC_DISABLE_SIGN_UP` | 禁止新的 OIDC 用户注册，但保留登录。                                                                               | 允许注册               |

## 实体设置

`entities` 中的每个类都必须继承对应的基础实体。子类可以重新声明列，以添加 GraphQL
元数据、索引、数据库类型或应用字段。

```typescript
import { BaseUser } from "@nest-boot/auth";
import { Field, ID, ObjectType } from "@nest-boot/graphql";
import { Entity, PrimaryKey, Property, t } from "@mikro-orm/postgresql";

@ObjectType()
@Entity()
export class User extends BaseUser {
  @Field(() => ID)
  @PrimaryKey({ type: t.bigint })
  override id!: string;

  @Field(() => String)
  @Property({ type: t.string })
  declare name: string;
}
```

包内提供 `BaseUser`、`BaseAccount`、`BaseSession`、`BaseVerification`、
`BaseWorkspace`、`BaseWorkspaceInvitation`、`BaseWorkspaceMember` 与 `BaseApiKey`。

Better Auth 1.7 使用必填的 `(issuer, accountId)` 组合标识账号。现有数据库在把
`issuer` 改为非空之前，应先回填稳定值并处理重复组合。`BaseSession` 会索引
`userId`，`BaseVerification` 会索引 `identifier`。修改配置实体后应重新生成应用迁移。
