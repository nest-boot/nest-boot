---
title: "Email and Password"
description: "Implement signup, verification, password recovery, and email changes."
---

`AuthService` exposes stable application-facing types instead of Better Auth's
inferred API types. A GraphQL resolver, REST controller, or other adapter can
delegate directly to these methods.

## Authentication

- `signUp()` maps to email signup and accepts a post-verification `callbackURL`;
- `signIn()` authenticates an email and password and supports `rememberMe`;
- `signOut()` invalidates the current session.

Pass `{ returnHeaders: true }` when the transport must forward the complete
`Set-Cookie` response. With `rememberMe: false`, sign-in creates a browser-session
cookie rather than one that persists across browser restarts.

## Email Verification

Email verification is required by default. In that mode, `signUp()` creates the
user without creating a session. The client should:

1. pass the desired destination as the signup `callbackURL`;
2. show a check-email state;
3. allow resending through `sendVerificationEmail()`;
4. handle the callback's success or `error` query parameter;
5. ask the verified user to sign in and continue to the original destination.

The built-in sender uses the globally registered `Mailer`. Override it with
`emailVerification.sendVerificationEmail` when the application needs templates,
queues, or another delivery provider.

## Password Recovery

`requestPasswordReset()` sends a callback link without revealing whether the
account exists. The callback redirects to the application reset page with its
token, and `resetPassword()` consumes that token. An authenticated user changes
their current password with `changePassword()`.

Override `emailAndPassword.sendResetPassword` to customize reset delivery.
Password hashing and verification use `HashService` by default and can be
replaced through `emailAndPassword.password`.

## Email Changes

Enable `user.changeEmail.enabled` to expose `changeEmail()`. The built-in flow is
deliberately two-stage:

1. the current address receives a confirmation link;
2. the new address receives a verification link;
3. the account changes only after the new address is verified.

Override the first message with
`user.changeEmail.sendChangeEmailConfirmation` and the second with
`emailVerification.sendVerificationEmail`.

## Other Account Operations

`AuthService` also exposes `updateUser()`, `setPassword()`, `deleteUser()`,
`verifyPassword()`, `listAccounts()`, `unlinkAccount()`, `getAccessToken()`,
`refreshToken()`, and `accountInfo()`. Operations that validate the current
request accept Fetch-standard `HeadersInit`.
