---
title: "API Keys"
description: "Authenticate personal and workspace automation with scoped API keys."
---

`ApiKeyService` manages keys owned by either a user or a workspace.

- A **user key** restores its user and may access a selected workspace only
  while that user remains an active member.
- A **workspace key** is an independent service identity. It restores its
  workspace without creating a current user or workspace member.

Users manage their own keys. Active workspace members manage workspace keys
when their resolved workspace ability grants the corresponding
`apiKey:create`, `apiKey:read`, `apiKey:update`, or `apiKey:delete` permission.

## Service API

- `getUserApiKey`, `createUserKey`, `updateUserKey`, and `deleteUserKey`;
- `getWorkspaceApiKey`, `createWorkspaceKey`, `updateWorkspaceKey`, and `deleteWorkspaceKey`;
- `getUserListFilter` and `getWorkspaceListFilter`;
- `validate(plaintextKey)` and `recordUsage(apiKey)`.

Create methods return the plaintext key exactly once. The database stores a
SHA-256 hash of the complete key, the display-safe `start` and `prefix`, enabled
state, permissions, expiration, and usage timestamps. Successful authenticated
requests update `lastUsedAt` automatically.

## Permission Values

The auth package stores and evaluates permissions as `string[]`. Applications
define closed user and workspace permission catalogs. `ApiKeyService` validates
permission values against those catalogs during key creation and updates.

```typescript
const workspacePermissions = [
  "workspace:update",
  "workspaceMember:create",
] as const;

type WorkspacePermission = (typeof workspacePermissions)[number];

const userKeyPermissions = ["user:get", ...workspacePermissions] as const;
```

In the example, entity properties, GraphQL inputs, and database columns all use
strings. The application keeps an `as const` catalog for form options and local
TypeScript types. A workspace key accepts only configured workspace
permissions; a user key accepts the union of the configured user and workspace
catalogs. Malformed, duplicate, and unknown values are rejected. PostgreSQL
persists the values in `text[]` columns.

## Transport

Send API keys with the Bearer scheme:

```http
Authorization: Bearer sk-4tR9s...
```

`x-api-key` is not supported. Cookie session resolution runs first. When no
valid Cookie session exists, the Bearer credential is treated as an API key.

Use `@CurrentApiKey()` when a handler needs the credential that authenticated
the request:

```typescript
import { CurrentApiKey } from "@nest-boot/auth";

audit(@CurrentApiKey() apiKey: ApiKey | null) {
  return apiKey;
}
```

User-key permissions are intersected with the owning user's user ability and,
for workspace routes, the user's current workspace-member ability. Workspace
keys are service identities and are evaluated directly from their validated
workspace permission list.
