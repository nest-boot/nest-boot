---
title: "邮箱与密码"
description: "实现注册、邮箱验证、密码找回与邮箱修改。"
---

`AuthService` 使用稳定的应用层类型，不向外暴露 Better Auth 推导的 API 类型。
GraphQL Resolver、REST Controller 或其他适配器可以直接委托这些方法。

## 身份认证

- `signUp()` 对应邮箱注册，并接受验证完成后的 `callbackURL`；
- `signIn()` 使用邮箱和密码登录，并支持 `rememberMe`；
- `signOut()` 使当前会话失效。

传输层需要转发完整的 `Set-Cookie` 响应时，传入 `{ returnHeaders: true }`。
`rememberMe: false` 会创建随浏览器会话结束的 Cookie，而不是跨浏览器重启保存的 Cookie。

## 邮箱验证

默认要求验证邮箱。在这种模式下，`signUp()` 只创建用户，不创建会话。客户端应：

1. 将验证完成后的目标地址作为 `callbackURL` 传给注册接口；
2. 显示“检查邮箱”状态；
3. 允许通过 `sendVerificationEmail()` 重发验证邮件；
4. 处理回调成功或 `error` 查询参数；
5. 让验证完成的用户登录并继续原目标页面。

内置发送函数使用全局注册的 `Mailer`。需要模板、队列或其他投递服务时，可以通过
`emailVerification.sendVerificationEmail` 覆盖。

## 密码找回

`requestPasswordReset()` 发送回调链接，并且不会泄露账户是否存在。回调会把 token
带到应用的密码重置页，随后由 `resetPassword()` 消费。已登录用户使用
`changePassword()` 修改当前密码。

通过 `emailAndPassword.sendResetPassword` 自定义重置邮件。密码哈希与验证默认使用
`HashService`，也可以通过 `emailAndPassword.password` 替换。

## 修改邮箱

启用 `user.changeEmail.enabled` 后可以使用 `changeEmail()`。内置流程分为两步：

1. 当前邮箱收到修改确认链接；
2. 新邮箱收到验证链接；
3. 新邮箱验证完成后才修改账户。

通过 `user.changeEmail.sendChangeEmailConfirmation` 覆盖第一封邮件，通过
`emailVerification.sendVerificationEmail` 覆盖第二封邮件。

## 其他账号操作

`AuthService` 还提供 `updateUser()`、`setPassword()`、`deleteUser()`、
`verifyPassword()`、`listAccounts()`、`unlinkAccount()`、`getAccessToken()`、
`refreshToken()` 与 `accountInfo()`。需要校验当前请求的操作会从 `RequestContext`
读取 Cookie 与 Authorization Header，Controller 或 Resolver 无需逐层传递 Headers。
