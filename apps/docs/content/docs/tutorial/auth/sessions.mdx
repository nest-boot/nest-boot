---
title: "Sessions"
description: "Resolve, list, and revoke authenticated sessions."
---

Browser authentication uses HttpOnly Cookie sessions. Same-origin GraphQL and
auth requests must enable credentials so the browser stores and returns those
cookies. API keys use a separate Bearer flow described in
[API Keys](/docs/tutorial/auth/api-keys).

## Current Identity

`AuthMiddleware` resolves the authenticated application `User` and `Session`
entities into `RequestContext`. Transport code should use decorators instead of
reading context tokens directly.

```typescript
import { CurrentSession, CurrentUser } from "@nest-boot/auth";

profile(
  @CurrentUser() user: User,
  @CurrentSession() session: Session,
) {
  return { user, session };
}
```

Both decorators return `null` when the corresponding identity is unavailable,
allowing public handlers to declare nullable parameters explicitly.

## SessionService

`SessionService` provides:

- `getSession()` — resolves the current application entities;
- `listSessions()` — lists the current user's active sessions;
- `revokeSession(id)` — revokes one session by its public ID;
- `revokeOtherSessions()` — keeps only the current session;
- `revokeSessions()` — revokes every session for the current user;
- `setSession(token)` — selects an application-created session for the current
  browser response, such as during impersonation.

Each method reads the current request headers from `RequestContext`. Transport
code does not need to convert or forward Express headers.

Session lists preserve backend order and expose the non-secret session ID used
to revoke a specific session. Authentication tokens remain internal and in the
HttpOnly browser cookie. A UI should identify the current session and avoid
presenting it as an ordinary remote-device revoke action.

`setSession()` writes the signed browser cookies through the request-scoped
`cookies()` store and expires cached session and account cookies. The example
uses it when `UserService.impersonateUser()` and `stopImpersonating()` switch
browser identity.

For administrative revocation, `UserService.revokeUserSessions(user)` removes
both the user's own sessions and impersonation sessions started by that user.
Revoked impersonation sessions cannot restore the administrator's identity;
the impersonated user's independent sessions remain valid.

When PostgreSQL RLS is enabled, application entity lookup runs in an isolated
auth context with RLS disabled. Business database roles therefore do not need
direct access to authentication tables, and the parent request context remains
unchanged.
