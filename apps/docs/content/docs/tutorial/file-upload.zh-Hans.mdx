---
title: "文件上传"
description: "使用 S3 兼容存储处理文件上传，支持 MIME 类型验证和文件大小限制。"
---

`@nest-boot/file-upload` 模块为 S3 兼容存储创建带约束的 presigned POST，通过 GraphQL 暴露上传参数，支持服务端直接上传，并把已接受的临时对象复制到按日期组织的永久 key。

## 安装

```bash
pnpm add @nest-boot/file-upload @nest-boot/s3 @aws-sdk/client-s3 @aws-sdk/s3-presigned-post
```

`@nest-boot/s3` 是对等依赖，必须在应用中注册一次。它提供 `FileUploadModule` 消费的全局 `S3Client`。

## 模块注册

```typescript
import { FileUploadModule } from "@nest-boot/file-upload";
import { S3Module } from "@nest-boot/s3";
import { Module } from "@nestjs/common";
import { ConfigService } from "@nestjs/config";

const FileUploadDynamicModule = FileUploadModule.registerAsync({
  inject: [ConfigService],
  useFactory: (configService: ConfigService) => ({
    bucket: configService.getOrThrow("S3_BUCKET"),
    expires: 3600,
    limits: [
      {
        fileSize: 10 * 1024 * 1024,
        mimeTypes: ["image/*", "application/pdf"],
      },
    ],
  }),
});

@Module({
  imports: [S3Module, FileUploadDynamicModule],
})
export class AppModule {}
```

静态导入的 `S3Module` 会读取 `S3_ENDPOINT_URL`、`S3_ACCESS_KEY_ID`、`S3_SECRET_ACCESS_KEY`、`S3_REGION` 和 `S3_FORCE_PATH_STYLE`。显式配置和异步配置方式请参阅 [S3 教程](/docs/tutorial/s3)。

### 配置选项

| 选项      | 描述                                                                                   |
| --------- | -------------------------------------------------------------------------------------- |
| `bucket`  | S3 存储桶名称                                                                          |
| `url`     | 可选的公开前缀，用于替换生成的 presigned POST URL 的 origin/path                       |
| `expires` | presigned POST 的有效秒数，默认为 `3600`                                               |
| `limits`  | 可接受的 `{ fileSize, mimeTypes }` 组合；MIME pattern 使用 micromatch 的 glob 匹配语义 |

## 用法

### 创建预签名上传

`FileUploadModule` 会注册 `createFileUploads` GraphQL Mutation。它接收包含文件名、字节数和 MIME 类型的数组，按 `limits` 验证每个条目，并返回 presigned POST URL 和必需的表单字段：

```graphql
mutation CreateFileUploads($input: [FileUploadInput!]!) {
  createFileUploads(input: $input) {
    url
    fields {
      name
      value
    }
  }
}
```

客户端必须把全部返回字段、文件内容以及相同的 `Content-Type` 提交到返回的 URL。生成的临时 key 使用 `tmp/` 前缀。

### 持久化临时对象

客户端上传成功后，使用 `persist()` 把临时对象复制到 `files/YYYY/MM/DD/...`：

```typescript
import { FileUploadService } from "@nest-boot/file-upload";
import { Injectable } from "@nestjs/common";

@Injectable()
export class FileService {
  constructor(private readonly fileUploadService: FileUploadService) {}

  async persistFile(tempFileUrl: string): Promise<string> {
    return await this.fileUploadService.persist(tempFileUrl);
  }
}
```

`persist()` 只返回永久对象 URL。大小和 MIME 验证发生在 `create()` 创建预签名上传时，而不是 `persist()` 阶段。复制操作不会删除临时对象。

### 服务端直接上传

服务器已经持有文件数据时可使用 `upload()`。第三个参数传入 `true`，会立即把结果复制到永久存储：

```typescript
const url = await fileUploadService.upload(
  pdfBuffer,
  { "Content-Type": "application/pdf" },
  true,
);
```

## 最佳实践

1. **严格 MIME 类型** — 只允许应用实际需要的 MIME 类型。

2. **合理的大小限制** — 定义一个或多个 `limits` 条目，把最大字节数与 MIME glob pattern 配对。

3. **清理临时对象** — `persist()` 会复制但不会删除 `tmp/` 源对象；请为临时 key 配置 S3 生命周期规则。
