`@nest-boot/graphql` 模块为 NestJS 提供预配置的 [Apollo Server](https://www.apollographql.com/docs/apollo-server/) GraphQL 层，支持代码优先的模式生成、全局异常过滤和可选的本地 Landing Page。配套模块提供[操作日志](#graphql-日志)、[查询复杂度限流](#graphql-限流)和[游标分页](#graphql-连接)。

如需通过 GraphQL Mutation 创建分阶段上传，请参阅
[分阶段上传指南中的 GraphQL 集成](/docs/tutorial/staged-upload#graphql-集成)。

## 安装

```bash
pnpm add @nest-boot/graphql @nestjs/graphql @nestjs/apollo @apollo/server graphql
```

如需使用下文的 Zod 输入验证，还需要安装：

```bash
pnpm add @nest-boot/validator zod
```

## 模块注册

### 基本注册

```typescript
import { Module } from "@nestjs/common";
import { GraphQLModule } from "@nest-boot/graphql";

@Module({
  imports: [GraphQLModule.forRoot({})],
})
export class AppModule {}
```

模块自动配置 Apollo Server 的合理默认值：

- 默认端点路径 `/graphql`，遵循 NestJS 全局前缀
- 代码优先自动生成 Schema（`schema.gql`）
- Schema 排序输出
- 全局 `GraphQLExceptionFilter` 错误处理
- 除非显式设置 `graphiql: false`，否则启用 GraphiQL

### 异步注册

```typescript
import { GraphQLModule } from "@nest-boot/graphql";
import { ConfigService } from "@nestjs/config";

const GraphQLDynamicModule = GraphQLModule.forRootAsync({
  inject: [ConfigService],
  useFactory: (configService: ConfigService) => ({
    graphiql: configService.get("NODE_ENV") !== "production",
  }),
});
```

### 全局前缀

Nest Boot 默认配置为 `path: "/graphql"` 和 `useGlobalPrefix: true`，由官方
`@nestjs/graphql` driver 应用全局前缀，无需手动拼接。
未设置全局前缀时，端点为 `/graphql`。

```typescript
GraphQLModule.forRoot({});
// 在 bootstrap 中：
app.setGlobalPrefix("api");
// 端点：/api/graphql
```

`forRoot` 和 `forRootAsync` 均可覆盖这两个默认值。
设置 `useGlobalPrefix: false` 可让 GraphQL 端点不受全局前缀影响；
通过 `path` 可修改相对路由。上游 `@nestjs/graphql` 默认不启用
`useGlobalPrefix`，Nest Boot 在此基础上默认开启。

未设置全局前缀的应用升级时，需将客户端地址更新为 `/graphql`。
若要保留原来的固定端点，可显式配置
`{ path: "/api/graphql", useGlobalPrefix: false }`。

## 定义类型

`@nest-boot/graphql` 重新导出了 `@nestjs/graphql` 的所有内容，因此你可以使用一组装饰器同时定义 GraphQL 类型和实体模型：

下面的实体示例还使用了 MikroORM，请先完成 [MikroORM 安装](./database#安装)，包括 `@mikro-orm/decorators`。

```typescript
import { t } from "@mikro-orm/core";
import { Entity, PrimaryKey, Property } from "@mikro-orm/decorators/legacy";
import { Field, ID, ObjectType } from "@nest-boot/graphql";

@ObjectType()
@Entity()
export class User {
  @Field(() => ID)
  @PrimaryKey({ type: t.bigint })
  id!: string;

  @Field(() => String)
  @Property({ type: t.string })
  name!: string;

  @Field(() => String)
  @Property({ type: t.string })
  email!: string;

  @Field(() => Date)
  @Property({ type: t.datetime, defaultRaw: "now()" })
  createdAt: Date = new Date();
}
```

### 输入类型

使用 `@InputType()` 定义 Mutation 输入，并配合 `@nest-boot/validator` 进行
Zod 验证：

```typescript
import { Field, InputType, ID } from "@nest-boot/graphql";
import { ZodField } from "@nest-boot/validator";
import { z } from "zod";

@InputType()
export class CreateUserInput {
  @ZodField(z.string().min(1))
  @Field(() => String)
  name!: string;

  @ZodField(z.email())
  @Field(() => String)
  email!: string;

  @ZodField(z.string().optional())
  @Field(() => ID, { nullable: true })
  workspaceId?: string;
}
```

使用对应的 validator helper 包装 GraphQL mapped type，让 GraphQL 字段元数据
和 Zod schema 一起传递到派生类：

```typescript
import { PartialType } from "@nestjs/graphql";
import { ZodPartialType } from "@nest-boot/validator";

@InputType()
export class UpdateUserInput extends ZodPartialType(
  CreateUserInput,
  PartialType,
) {}
```

按照[验证指南](/docs/tutorial/validator#启用-nestjs-验证)全局注册
`ZodValidationPipe`。验证失败时，`GraphQLExceptionFilter` 会返回 Apollo 风格的
用户输入错误，并在 `extensions` 中保留字段级详情：

```json
{
  "errors": [
    {
      "message": "Validation failed",
      "path": ["createUser"],
      "extensions": {
        "code": "BAD_USER_INPUT",
        "validationErrors": [
          {
            "code": "invalid_format",
            "field": ["email"],
            "message": "Invalid email address"
          }
        ]
      }
    }
  ]
}
```

顶层 `path` 是 GraphQL 的解析器响应路径；每个 `field` 是无效输入值的路径，
其中可以包含数字形式的数组索引。

## 解析器

```typescript
import {
  Args,
  ID,
  Mutation,
  Parent,
  Query,
  ResolveField,
  Resolver,
} from "@nest-boot/graphql";
import { NotFoundException } from "@nestjs/common";

import { User } from "./user.entity";
import { UserService } from "./user.service";
import { CreateUserInput } from "./inputs/create-user.input";

@Resolver(() => User)
export class UserResolver {
  constructor(private readonly userService: UserService) {}

  @Query(() => User)
  async user(@Args("id", { type: () => ID }) id: string): Promise<User> {
    const user = await this.userService.findOne({ id });

    if (!user) {
      throw new NotFoundException("User not found");
    }

    return user;
  }

  @Mutation(() => User)
  async createUser(@Args("input") input: CreateUserInput): Promise<User> {
    return await this.userService.create(input);
  }

  @ResolveField(() => String)
  displayName(@Parent() user: User): string {
    return user.name;
  }
}
```

## GraphQL 连接

`@nest-boot/graphql-connection` 模块提供遵循 [Relay 连接规范](https://relay.dev/graphql/connections.htm) 的游标分页。集成 MikroORM，生成类型安全的分页查询，支持过滤、排序和全文搜索。

### 安装

```bash
pnpm add @nest-boot/graphql-connection @mikro-orm/core
```

在 `CommonModule`（或根模块）中注册：

```typescript
import { GraphQLConnectionModule } from "@nest-boot/graphql-connection";

@Global()
@Module({
  imports: [GraphQLConnectionModule],
})
export class CommonModule {}
```

### 定义连接

使用 `ConnectionBuilder` 定义哪些字段支持过滤、排序和搜索：

```typescript
import { ArgsType, ObjectType } from "@nest-boot/graphql";
import { ConnectionBuilder } from "@nest-boot/graphql-connection";
import { User } from "./user.entity";

export const { Connection, ConnectionArgs } = new ConnectionBuilder(User)
  .addField({
    field: "id",
    type: "string",
    filterable: true,
  })
  .addField({
    field: "name",
    type: "string",
    filterable: true,
    sortable: true,
    searchable: true,
  })
  .addField({
    field: "email",
    type: "string",
    filterable: true,
    searchable: true,
  })
  .addField({
    field: "created_at",
    replacement: "createdAt",
    type: "date",
    filterable: true,
    sortable: true,
  })
  .addField({
    field: "is_active",
    replacement: "isActive",
    type: "boolean",
    filterable: true,
  })
  .build();

@ArgsType()
export class UserConnectionArgs extends ConnectionArgs {}

@ObjectType()
export class UserConnection extends Connection {}
```

`addField` 的关键选项：

- **`replacement`** — 将客户端字段名映射到不同的实体属性（例如 `created_at` → `createdAt`）
- **`filterable`** — 启用 MongoDB 风格过滤（`$eq`、`$ne`、`$gt`、`$in` 等）
- **`sortable`** — 启用按此字段排序
- **`searchable`** — 启用人性化搜索语法（`field:value`）
- **`fulltext`** — 使用 PostgreSQL 全文搜索

### 在解析器中使用

注入 `ConnectionManager` 执行分页查询：

```typescript
import {
  Args,
  Query,
  Resolver,
  ResolveField,
  Parent,
} from "@nest-boot/graphql";
import { ConnectionManager } from "@nest-boot/graphql-connection";

import { User } from "./user.entity";
import {
  UserConnection,
  UserConnectionArgs,
} from "./user.connection-definition.js";
import {
  PostConnection,
  PostConnectionArgs,
} from "./post.connection-definition.js";

@Resolver(() => User)
export class UserResolver {
  constructor(private readonly cm: ConnectionManager) {}

  @Query(() => UserConnection)
  async users(@Args() args: UserConnectionArgs): Promise<UserConnection> {
    return await this.cm.find(UserConnection, args);
  }

  // 嵌套连接：解析用户的文章
  @ResolveField(() => PostConnection)
  async posts(
    @Parent() user: User,
    @Args() args: PostConnectionArgs,
  ): Promise<PostConnection> {
    return await this.cm.find(PostConnection, args, {
      where: { author: user },
    });
  }
}
```

`cm.find()` 的第三个参数接受额外的 `where` 过滤条件，会与客户端的 filter/query 参数合并。适用于：

- 将查询范围限定到当前工作区或用户
- 实现软删除（例如 `where: { deletedAt: null }`）
- 嵌套连接字段

### 分页

查询必须且只能提供 `first` 或 `last`，且值为 1 至 100 的整数。`after` 搭配 `first`，`before` 搭配 `last`。分页参数缺失、冲突或超出范围时返回 `BAD_USER_INPUT`。

```graphql
# 正向分页
query {
  users(first: 10, after: "cursor_abc") {
    edges {
      node {
        id
        name
      }
      cursor
    }
    pageInfo {
      hasNextPage
      endCursor
    }
  }
}

# 反向分页
query {
  users(last: 10, before: "cursor_xyz") {
    edges {
      node {
        id
        name
      }
    }
    pageInfo {
      hasPreviousPage
      startCursor
    }
  }
}
```

### 过滤

MongoDB 风格的过滤语法，支持操作符：`$eq`、`$ne`、`$gt`、`$gte`、`$lt`、`$lte`、`$in`、`$nin`、`$and`、`$or`、`$regex`。

```graphql
query {
  users(filter: { name: { $regex: "john" }, is_active: { $eq: true } }) {
    edges { node { id name } }
  }
}
```

### 搜索查询

人性化的搜索语法，映射到可过滤/可搜索字段：

```graphql
query {
  users(query: "john email:john@example.com") {
    edges {
      node {
        id
        name
        email
      }
    }
  }
}
```

## GraphQL 限流

`@nest-boot/graphql-rate-limit` 模块提供 Shopify 风格的查询复杂度限流，并通过可插拔存储驱动实现漏桶算法。

### 安装

```bash
pnpm add @nest-boot/graphql-rate-limit @nest-boot/redis ioredis
```

### 注册

```typescript
import { GraphQLRateLimitModule } from "@nest-boot/graphql-rate-limit";
import { RedisModule } from "@nest-boot/redis";

@Module({
  imports: [RedisModule.register({}), GraphQLRateLimitModule],
})
export class CommonModule {}
```

无需动态注册即可直接导入限流模块。默认复用 `RedisModule` 提供的 Redis 实例，连接配置和 `REDIS_URL` 解析统一由 `@nest-boot/redis` 处理。共享连接由 `RedisModule` 负责关闭，限流驱动不会关闭它。

驱动选择按以下优先级执行：

1. 显式自定义 `driver`。
2. 显式 `connection`，使用该配置创建独立连接，并由限流驱动负责关闭。
3. 已注册的 `RedisModule` 提供的共享实例。
4. 没有共享实例时使用进程内 memory 驱动。

**迁移说明：** 限流模块不再读取 `REDIS_URL`。原来仅设置该环境变量的应用需要注册 `RedisModule` 才能继续使用 Redis 限流。显式 `connection` 也不再与环境变量配置合并；如需使用环境变量或共享配置，请将连接配置移至 `RedisModule.register()` 或 `registerAsync()`，并省略限流模块的 `connection`。

Memory 驱动适合本地开发和单进程应用，但不同进程或副本之间不会共享限流桶。如果配额需要全局共享，请使用 Redis 或自定义分布式驱动。

需要调整令牌桶阈值或显式指定驱动时，使用 `forRoot()`。当前插件会拒绝 requested query cost 大于等于 `1000` 的查询。

```typescript
import {
  GraphQLRateLimitDriver,
  GraphQLRateLimitModule,
  MemoryGraphQLRateLimitDriver,
} from "@nest-boot/graphql-rate-limit";

const driver: GraphQLRateLimitDriver = new MemoryGraphQLRateLimitDriver();

@Module({
  imports: [
    GraphQLRateLimitModule.forRoot({
      driver,
      maximumAvailable: 1000, // 令牌桶容量
      restoreRate: 50, // 每秒恢复的点数
    }),
  ],
})
export class CommonModule {}
```

自定义驱动需要继承 `GraphQLRateLimitDriver`，并实现具备原子性的 `update()` 方法。正数 `points` 消耗容量，负数则恢复容量。如果创建驱动需要注入其他依赖，可以使用 `forRootAsync()`。

如需传入由外部管理的自定义 Redis 实例，可将 `new RedisGraphQLRateLimitDriver(redis, false)` 作为 `driver`。第二个参数表示驱动不拥有连接，由调用方负责关闭。省略该参数时，驱动仍默认负责关闭传入的客户端。

### 自定义复杂度

使用 `@nest-boot/graphql` 的 `GraphQLModule` 时，`Query`、`Mutation`、`ResolveField` 和 `Field` 对返回单个具体对象的字段默认使用返回类型上的静态 `complexity`。生成的 Connection 及其子类提供这个回调。要自定义列表成本或覆盖自动推断的默认值，请显式设置 `complexity`，包括设为 0。

限流器按请求条数为每条边预留 1 点，再根据 resolver 实际返回的边数结算这部分成本。只查询游标时也适用。生成的 `Edge.node` 自身计 0 点，`node` 下选中的字段按各自的规则计费。回调按一次归一化后的 `query` 和 `filter` 计费。每个比较和逻辑组计 1 点，`$in` 等数组比较按元素计费，最低 1 点。

返回 `Count` 的独立字段使用生成的 `CountArgs` 中的过滤条件自动计费。每次计数收取 10 点基础成本，再按列表规则计一次筛选成本。`Count` 的子字段计 0 点。

resolver 成功后，自定义 `complexity` 回调在结算阶段通过 `resolved.result` 读取 GraphQL 序列化前的返回值，结果可能是 `null` 或 `undefined`。使用 `@nest-boot/graphql` 的 `Query`、`Mutation`、`ResolveField` 或 `Field` 时，结果类型沿用 NestJS `@Field` 的 `defaultValue` 推导规则。`ID` 和 `Int` 等标量引用推导为 `unknown`。

使用 `defineComplexity` 可以定义并导出可复用的回调。第一个参数直接传入返回类型，再将回调传给字段的 `complexity` 选项。

```typescript
import { defineComplexity } from "@nest-boot/graphql";

export const booksComplexity = defineComplexity(
  [Book],
  ({ childComplexity, resolved }) =>
    resolved ? (resolved.result?.length ?? 0) : 10 * (1 + childComplexity),
);
```

每个根 mutation 字段在结果成本之外默认加收 10 点基础费。可以在 `@Mutation` 上设置 `mutationComplexity` 来调整这个字段的基础费，包括设为 0。结果成本可以来自字段显式配置、返回类型的静态 `complexity`，或所选子字段。数值型 `complexity` 会与子字段成本相加，回调沿用查询字段的计费规则。

使用 `@Complexity()` 装饰器生成 `@complexity` Schema 指令。可以设置基础值，以及用于乘算该值的参数名：

```typescript
import { Complexity } from "@nest-boot/graphql-rate-limit";

@Resolver(() => User)
export class UserResolver {
  @Complexity({ value: 2, multipliers: ["first"] })
  @Query(() => UserConnection)
  async users(@Args() args: UserConnectionArgs) {
    return this.cm.find(UserConnection, args);
  }
}
```

查询开销会在响应 `extensions` 中返回，让客户端对 API 使用预算有完整的了解。

## 最佳实践

1. **全局 CommonModule** — 在一个 `@Global()` 的 `CommonModule` 中注册 `GraphQLModule`、`GraphQLConnectionModule` 和配套模块，供所有功能模块共享。

2. **双装饰器** — 在同一个类上使用 `@ObjectType()` + `@Entity()`，确保 GraphQL Schema 和数据库模式始终同步。

3. **连接定义** — 将连接构建器定义放在实体旁的 `*.connection-definition.ts` 文件中。

4. **字段替换** — 使用 `addField` 的 `replacement` 选项暴露客户端友好的 snake_case 字段名，同时内部映射到 camelCase 实体属性。

5. **作用域查询** — 始终传递 `where` 过滤条件，将连接查询限定到当前工作区或租户。
