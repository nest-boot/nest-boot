`@nest-boot/mailer` 模块提供由 [Nodemailer](https://nodemailer.com/) 驱动的邮件发送功能。

Nodemailer 10 自带 TypeScript 类型声明，无需安装 `@types/nodemailer`。

## 安装

```bash
npm install @nest-boot/mailer nodemailer@^10.0.16
# 或
pnpm add @nest-boot/mailer nodemailer@^10.0.16
```

## 基本用法

使用环境变量配置 SMTP transport：

```dotenv
SMTP_URL=smtp://user:password@smtp.example.com
SMTP_FROM="Example <no-reply@example.com>"
```

`SMTP_URL` 的优先级高于下面的拆分连接变量。端口可选：Nodemailer 会使用原生默认值，
`smtp://` 为 `587`，`smtps://` 为 `465`。

```dotenv
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_SECURE=false
SMTP_USERNAME=user@example.com
SMTP_PASSWORD=password
SMTP_FROM="Example <no-reply@example.com>"
```

只需导入一次 `MailerModule`。该模块是全局模块，功能模块无需重复导入即可注入
`Mailer`。

```typescript
import { Module } from "@nestjs/common";
import { MailerModule } from "@nest-boot/mailer";

@Module({
  imports: [MailerModule],
})
export class AppModule {}
```

需要显式配置连接时，使用 `MailerModule.register()` 或
`MailerModule.registerAsync()`；显式选项的优先级高于所有连接环境变量。
`SMTP_FROM` 仍是默认发件人，可通过 `sendMail({ from })` 覆盖。

## 发送邮件

`MailerModule` 将配置好的 Nodemailer transport 以 `Mailer` 类令牌导出。请从 `@nest-boot/mailer` 注入该令牌：

```typescript
import { Mailer } from "@nest-boot/mailer";
import { Injectable } from "@nestjs/common";

@Injectable()
export class NotificationService {
  constructor(private readonly mailer: Mailer) {}

  async sendWelcomeEmail(to: string, name: string): Promise<void> {
    await this.mailer.sendMail({
      to,
      subject: `欢迎，${name}！`,
      text: `${name}，感谢注册。`,
    });
  }
}
```

## SMTP 健康检查

`MailerModule` 提供 `MailerHealthIndicator`，默认不注册或执行检查。
如果 SMTP 可用性应影响应用的就绪状态，导入 `HealthCheckModule` 并显式注册：

```typescript
import {
  HealthCheckModule,
  HealthCheckRegistry,
} from "@nest-boot/health-check";
import { MailerHealthIndicator, MailerModule } from "@nest-boot/mailer";
import { Injectable, Module, type OnModuleInit } from "@nestjs/common";

@Injectable()
class SmtpReadiness implements OnModuleInit {
  constructor(
    private readonly registry: HealthCheckRegistry,
    private readonly mailerHealth: MailerHealthIndicator,
  ) {}

  onModuleInit(): void {
    if (this.mailerHealth.isSupported()) {
      this.registry.register(() => this.mailerHealth.check("mailer", 3000));
    }
  }
}

@Module({
  imports: [MailerModule, HealthCheckModule],
  providers: [SmtpReadiness],
})
export class AppModule {}
```

应用需声明与 Nest Boot 版本匹配的 `@nest-boot/health-check`，以及
`@nestjs/terminus@^12`。注册后，`GET /api/health` 包含 `mailer` 状态：
检查成功返回 HTTP 200，任一已注册检查失败返回 HTTP 503。
是否让 SMTP 故障影响就绪状态由应用决定；仅导入这两个模块不会改变现有检查。

`check(key = "mailer", timeout = 3000)` 调用 Nodemailer 的 `verify()`，
检查 DNS、连接建立、已配置的 TLS 和认证。它不发送邮件，也不验证发件人是否被接受或
邮件是否最终送达。支持普通 SMTP 和 SMTP 连接池。对于 JSON、Stream、Sendmail、
SES 和自定义 transport，`isSupported()` 返回 false；直接调用 `check()` 会返回
down，且不会执行验证。

超时仅限制健康检查的响应时间。Nodemailer 的验证不接受 abort signal，因此并发请求
以及超时后的探测会共用同一个未完成的验证，直到它结束。底层网络操作的时限由
Nodemailer 的连接、问候和 socket 超时配置控制。指示器不会关闭应用发送邮件使用的
transport。验证成功或失败后，下一次检查会重新验证，以便报告故障恢复。SMTP 错误
使用通用失败消息，避免通过健康接口暴露服务器回复或连接详情。

## 特性

- **Nodemailer 集成** - 通过 NestJS 依赖注入使用完整 Nodemailer API
- **环境变量配置** - 通过 `SMTP_*` 环境变量静态导入
- **SMTP 支持** - 标准 SMTP 传输配置
- **模板支持** - 结合 ViewModule 使用 HTML 模板
- **异步配置** - 基于工厂的环境或配置服务配置
