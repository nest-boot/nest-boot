`@nest-boot/command` 基于 Clipanion 4，参数类型由声明自动推导。`nb` 在项目目录执行 CLI 入口文件。`src/cli.ts` 与 `main.ts`、`repl.ts` 一样，通过 `bootstrap()` 启动共享的 `AppModule`，由 `CommandFactory.run()` 发现导入模块中的命令。

## 安装

```bash
pnpm add @nest-boot/command @nest-boot/request-context
```

要求 Node.js 24.21.0+、NestJS 12。在项目目录执行 `pnpm exec nb`，也可以定义 package script。

## 定义命令

```ts
import { BaseCommand, Command, Option } from "@nest-boot/command";

@Command({
  paths: [["greet"], ["hello", "user"]],
  usage: { description: "Greet a user." },
})
export class GreetCommand extends BaseCommand {
  name = Option.String({ required: true }); // string
  loud = Option.Boolean("--loud", false); // boolean
  prefix = Option.String("--prefix"); // string | undefined

  async execute(): Promise<void> {
    const name = this.loud ? this.name.toUpperCase() : this.name;
    this.context.stdout.write(`${this.prefix ?? "Hello"} ${name}!\n`);
  }
}
```

`Option.String`、`Option.Boolean`、`Option.Array` 等保留 Clipanion 的类型推导，不需要额外声明参数接口。校验和数字转换可以安装 `typanion`，通过 option 的 validator 配置。命令支持正常的 Nest 构造函数依赖注入；命令及其依赖必须是单例。

## 模块注册

```ts
// src/app/app.module.ts
import { CommandModule } from "@nest-boot/command";
import { Module } from "@nestjs/common";

import { GreetCommand } from "../greet.command.js";

@Module({ providers: [GreetCommand] })
class GreetingModule {}

@Module({ imports: [CommandModule, GreetingModule] })
export class AppModule {}
```

```ts
// src/cli.ts
import { CommandFactory } from "@nest-boot/command";

import { AppModule } from "./app/app.module.js";

async function bootstrap() {
  await CommandFactory.run(AppModule);
}

void bootstrap();
```

其他模块只需将命令类加入 `providers`，CLI 根模块导入这些模块即可自动发现，命令不需要 export。`paths` 支持多级命令和别名，路径重复会在执行前报错。

```bash
pnpm exec nb greet Alice --loud
pnpm exec nb hello user Alice --prefix Welcome
pnpm exec nb --help
pnpm exec nb greet --help
```

CLI 与 HTTP、REPL 共享 `AppModule`。Nest 应用初始化钩子仍会执行，需要兼容当前命令。后台服务遵循各自模块的生命周期配置。

## 入口与执行

开发环境依次查找 `src/cli.ts`、`dist/cli.js`；`NODE_ENV=production` 时依次查找 `dist/cli.js`、`src/cli.ts`。选中的入口报错时直接返回错误，不回退到旧产物。源码加载读取项目 tsconfig，并保留 Nest 装饰器元数据，支持相对 `.js` 导入解析到 `.ts` 源码以及 tsconfig 的 `paths` 和 `baseUrl` 导入解析。源码依赖中的 TSX 文件按项目的 JSX 编译配置转译。运行时转译不代替类型检查。编译后的 JavaScript 不需要源码或 tsconfig。

入口是可执行的 bootstrap 脚本，无需默认导出模块。在 CLI bootstrap 中调用一次 `CommandFactory.run(AppModule)`，内部会设置 `process.exitCode`；编译后的 `dist/cli.js` 也可以直接通过 Node.js 执行。`execute()` 可以返回退出码；帮助和成功执行返回 0，未知命令、无效参数、执行失败返回非零。执行结束后会关闭 Nest 上下文并调用资源清理钩子，失败时也会清理。

编程调用使用 `await CommandFactory.run(AppModule, { args: ["greet", "Alice"] })`，返回退出码并关闭上下文，不调用 `process.exit()`。`runCli({ cwd, production })` 执行项目入口，由入口负责 bootstrap 和 factory options，factory 内部设置退出码。factory options 支持输出流和帮助信息配置。

## 请求上下文

`CommandModule` 默认导入 `RequestContextModule`。每次 `CommandFactory.run()` 执行都建立独立上下文，`type` 为 `"command"`，ID 自动生成，并执行已注册的上下文中间件。命令执行和自定义错误处理使用同一个上下文。单例命令及服务可在方法内调用 `RequestContext.current()`、`RequestContext.get(token)`。应用初始化和关闭钩子在命令上下文之外执行。

上下文中没有存储的值会回退到 Nest 应用中的单例 provider；不存在、请求作用域或 transient provider 返回 `undefined`。

```ts
import { RequestContext } from "@nest-boot/request-context";

// 在 execute() 或注入的服务方法中使用：
const context = RequestContext.current();
console.log(context.type, context.id);
```

## 运行 example server 命令

仓库的 example server 已添加 `src/cli.ts`，启动现有 `AppModule`。`CommonModule` 导入 `CommandModule` 并注册 `GreetCommand`。配置示例所需服务并执行数据库迁移后，在仓库根目录运行：

```bash
pnpm --filter @nest-boot/example-server command --help
pnpm --filter @nest-boot/example-server command greet Alice --loud
```

输出为 `Hello ALICE!`。编译后也可在 `examples/server` 中执行 `node dist/cli.js greet Alice --loud`。命令共享应用的初始化钩子，示例仍需 PostgreSQL 和 Redis。

## 全局命令入口

包发布后可以全局安装：

```bash
npm install -g @nest-boot/command
nb --help
```

在应用目录运行 `nb`。项目自身仍需安装 `@nest-boot/command` 及其 peer dependencies，并提供 CLI 入口和 `CommandModule` 注册。全局安装提供执行入口；命令与依赖注入使用项目自己的实现。
