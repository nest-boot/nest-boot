---
title: "验证器"
description: "使用属性装饰器为 NestJS DTO 构建 Zod 验证。"
---

`@nest-boot/validator` 使用类属性装饰器构建 Zod object schema，并通过异步 Pipe 验证 NestJS DTO。它不依赖 `class-validator`、`class-transformer` 或 `@nest-boot/i18n`。

## 安装

```bash
pnpm add @nest-boot/validator zod
```

## 定义 DTO

`ZodField` 既可以直接接收 Zod schema，也可以接收一个以 Zod 命名空间为参数的工厂函数：

```typescript
import { toZodSchema, ZodField } from "@nest-boot/validator";
import { z } from "zod";

export class UserDto {
  @ZodField(z.string().email())
  email!: string;

  @ZodField((z) => z.string().min(8))
  password!: string;
}

export const UserSchema = toZodSchema(UserDto);
export type User = z.infer<typeof UserSchema>;
```

工厂函数会在 Zod 首次需要对应字段 schema 时延迟执行，因此既支持递归引用，
也可以减少装饰器中的重复导入。

`toZodSchema` 使用 DTO 的数据属性作为 schema 的推导输出，并排除实例方法。
但运行时 object shape 只包含使用 `ZodField` 声明的属性。未装饰属性仍会出现
在 `z.infer` 中，但默认不会被验证或保留在解析结果中。所有需要出现在解析结果
中的属性都必须添加 `ZodField`；属性声明也必须和 Zod 输出保持一致，特别是使用
coercion 或 transform 时：

```typescript
class QueryDto {
  @ZodField((z) => z.coerce.number().int().positive())
  page!: number;

  // 仅作为 DTO 静态类型，不会出现在解析结果中。
  label!: string;
}
```

字段装饰器支持继承。子类为同名属性声明 `ZodField` 时，会覆盖继承的 schema。

Schema 工厂会延迟求值，因此递归 DTO 可以直接引用自身组装后的 schema，无需
额外添加 `z.lazy`：

```typescript
class TreeDto {
  @ZodField(z.string())
  name!: string;

  @ZodField(() => toZodSchema(TreeDto).array())
  children!: TreeDto[];
}
```

## 映射 DTO

Nest 标准 mapped-type helper 不会复制第三方验证库持有的元数据。使用对应的
Zod-aware helper 包装它，派生类才能获得转换后的字段 schema：

```typescript
import { PartialType, PickType } from "@nestjs/mapped-types";
import { ZodPartialType, ZodPickType } from "@nest-boot/validator";

class UpdateUserDto extends ZodPartialType(UserDto, PartialType) {}

class UserEmailDto extends ZodPickType(UserDto, ["email"], PickType) {}
```

`ZodPartialType`、`ZodPickType`、`ZodOmitType` 和 `ZodIntersectionType` 也可以
不传 Nest factory，直接用于普通 DTO。派生 GraphQL 类型时，请传入
`@nestjs/graphql` 中对应的 helper，从而同时复制其字段元数据。映射 DTO 会保留
源 DTO 的未知字段策略，但不会继承 `ZodObject.configure` 回调，因为其中的
refinement 可能依赖已被移除或改为可选的字段。如派生 DTO 仍需对象级
refinement，请在派生 DTO 上添加新的 `@ZodObject` 装饰器。

## 启用 NestJS 验证

全局注册 `ZodValidationPipe`：

```typescript
import { ZodValidationPipe } from "@nest-boot/validator";
import { NestFactory } from "@nestjs/core";
import { AppModule } from "./app/app.module";

async function bootstrap() {
  const app = await NestFactory.create(AppModule);
  app.useGlobalPipes(new ZodValidationPipe());
  await app.listen(process.env.PORT ?? 4000);
}

void bootstrap();
```

Pipe 只验证包含 `ZodField` 或 `ZodObject` 元数据的类，其他参数保持原样通过。它使用 `safeParseAsync`，因此支持异步 refinement；同时会把 Zod 解析后的结果交给控制器，使 coercion 和 transform 生效。

输入无效时会抛出 `ZodValidationException`。HTTP 响应包含经过清理的
`validationErrors` 数组，每一项只有 `code`、`field` 和 `message`，不会返回
被拒绝的输入值。如需在异常过滤器中记录原始 Zod 错误，可以调用
`getZodError()`。

```json
{
  "statusCode": 400,
  "message": "Validation failed",
  "error": "Bad Request",
  "validationErrors": [
    {
      "code": "invalid_format",
      "field": ["email"],
      "message": "Invalid email address"
    }
  ]
}
```

也可以自定义异常：

```typescript
import { BadRequestException } from "@nestjs/common";
import { ZodValidationPipe } from "@nest-boot/validator";

new ZodValidationPipe({
  createValidationException: (error) =>
    new BadRequestException({
      message: "Invalid request",
      validationErrors: error.issues.map((issue) => ({
        code: issue.code,
        field: issue.path.map((segment) =>
          typeof segment === "symbol" ? segment.toString() : segment,
        ),
        message: issue.message,
      })),
    }),
});
```

## 对象级配置

对于已经包含字段装饰器的类，`ZodObject` 是可选的。空 DTO、未知字段策略或跨字段验证可以使用它：

```typescript
import { ZodField, ZodObject } from "@nest-boot/validator";
import { z } from "zod";

@ZodObject({
  unknownKeys: "strict",
  configure: (schema) =>
    schema.refine((value) => value.password === value.confirmPassword, {
      path: ["confirmPassword"],
      message: "Passwords do not match",
    }),
})
class PasswordDto {
  @ZodField(z.string().min(8))
  password!: string;

  @ZodField(z.string())
  confirmPassword!: string;
}
```

`unknownKeys` 支持 `strip`（默认）、`strict` 和 `passthrough`。

## 嵌套 DTO

嵌套装饰类可以在工厂函数中配合 `toZodSchema` 使用：

```typescript
class AddressDto {
  @ZodField((z) => z.string().min(1))
  city!: string;
}

class UserDto {
  @ZodField(() => toZodSchema(AddressDto))
  address!: AddressDto;

  @ZodField((z) => z.array(toZodSchema(AddressDto)))
  previousAddresses!: AddressDto[];
}
```
