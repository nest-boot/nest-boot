---
title: "迁移到版本 8"
description: "将 Nest Boot 应用升级到 NestJS 12 和原生 ESM。"
---

版本 8 是所有 `@nest-boot/*` 包面向 NestJS 12 的发布线。所有包均以原生
ESM 发布，并要求 Node.js 26 或更高版本。

## 升级依赖

同时升级 Nest Boot 与 NestJS 包：

```bash
pnpm up "@nest-boot/*@^8" "@nestjs/common@^12" "@nestjs/core@^12"
```

GraphQL 应用还应使用 `@nestjs/graphql@^14` 与 `@nestjs/apollo@^14`；
BullMQ 应用应使用 `@nestjs/bullmq@^12`。集成 MikroORM 的包要求 MikroORM 7。

应用层面的 NestJS 破坏性变更请参考上游
[NestJS 迁移指南](https://docs.nestjs.com/migration-guide)。

## 启用 ESM

在应用的 `package.json` 中加入 `"type": "module"`。将 `module` 和
`moduleResolution` 设置为 `NodeNext`，并使用 ES2023 或更高的编译目标：

```json
{
  "compilerOptions": {
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "target": "ES2023"
  }
}
```

TypeScript 源码中的相对导入需要显式添加 `.js` 扩展名。请将 CommonJS 的
`require()` 与 `module.exports` 改为 ESM import/export。版本 8 的 package
exports 只提供 `import` 入口，不再提供 CommonJS `require` 入口。

## 更新相关集成

- 将 Apollo Playground 配置替换为 `graphiql`。
- 使用 MikroORM 时升级到版本 7，并从受支持的包入口（例如
  `@mikro-orm/sql` 和 `@mikro-orm/sqlite`）导入 SQL 类型与驱动。
- 文件上传应用必须安装并注册全局 `@nest-boot/storage` 模块。从
  `FileUploadModule` 选项中移除 `client` 与 `bucket`，改为配置 `StorageModule`。
  该模块会全局提供 `S3Client` 与 `Storage`，静态注册会读取 `STORAGE_ENDPOINT_URL`、
  `STORAGE_INTERNAL_ENDPOINT_URL`、`STORAGE_PUBLIC_ENDPOINT_URL`、`STORAGE_ACCESS_KEY_ID`、`STORAGE_SECRET_ACCESS_KEY`、`STORAGE_REGION`、
  `STORAGE_FORCE_PATH_STYLE`、`STORAGE_BUCKET` 和 `STORAGE_ROOT_PATH`。
- 切换 TypeScript 模块解析后，重新生成文件和迁移，确保生成的导入带有有效的
  ESM 扩展名。

## 仓库测试

Nest Boot 版本 8 使用基于 SWC 的 Vitest 替代 Jest。贡献者可以通过
`pnpm test` 和 `pnpm test:e2e` 运行单元测试与端到端测试。
