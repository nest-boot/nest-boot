---
title: "迁移到版本 8"
description: "将 Nest Boot 应用升级到 NestJS 12 和原生 ESM。"
---

版本 8 是所有 `@nest-boot/*` 包面向 NestJS 12 的发布线。所有包均以原生
ESM 发布，并要求 Node.js 24.4 或更高版本。

## 升级依赖

同时升级 Nest Boot 与 NestJS 包：

```bash
pnpm up "@nest-boot/*@^8" "@nestjs/common@^12" "@nestjs/core@^12"
```

GraphQL 应用还应使用 `@nestjs/graphql@^14` 与 `@nestjs/apollo@^14`；
BullMQ 应用应使用 `@nestjs/bullmq@^12`。集成 MikroORM 的包要求 MikroORM 7。

应用层面的 NestJS 破坏性变更请参考上游
[NestJS 迁移指南](https://docs.nestjs.com/migration-guide)。

## 启用 ESM

在应用的 `package.json` 中加入 `"type": "module"`。将 `module` 和
`moduleResolution` 设置为 `NodeNext`，并使用 ES2023 或更高的编译目标：

```json
{
  "compilerOptions": {
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "target": "ES2023"
  }
}
```

TypeScript 源码中的相对导入需要显式添加 `.js` 扩展名。请将 CommonJS 的
`require()` 与 `module.exports` 改为 ESM import/export。版本 8 的 package
exports 只提供 `import` 入口，不再提供 CommonJS `require` 入口。

## 更新相关集成

- 将 Apollo Playground 配置替换为 `graphiql`。
- 使用 MikroORM 时升级到版本 7，并从受支持的包入口（例如
  `@mikro-orm/sql` 和 `@mikro-orm/sqlite`）导入 SQL 类型与驱动。
- 将 `@nest-boot/file-upload` 替换为 `@nest-boot/staged-upload`。核心模块现在是
  与传输层无关的全局模块；GraphQL 应用还必须安装并导入
  `@nest-boot/graphql-staged-upload`，才能继续使用 `createStagedUploads` Mutation。
  `StagedUploadInput`、`StagedUpload` 与 `StagedUploadField` 改从 GraphQL 包导入；
  与传输层无关的服务类型使用 `StagedUploadRequest` 与 `StagedUploadResult`。
- 移除 `@nest-boot/row-level-security`，使用 MikroORM 7.2 的官方 PostgreSQL 或
  PGlite 驱动、`@Entity({ policies })` 和 `em.setSessionContext()`，替代自定义
  驱动、装饰器、运行时状态和 `AuthTransactionContext`。迁移类改用官方
  `Migration` / `Migrator`。执行 schema diff 前，先将已有策略声明到实体元数据；
  数据库角色与权限仍需显式创建和授权。通过 `MikroOrmModuleOptions.session`
  初始化请求 session，并在业务事务开始前更新。详见 [MikroORM RLS 文档](https://mikro-orm.io/docs/row-level-security)。
- 将认证权限的资源名更新为 CASL subject type 的原始值。内置目录现在使用
  `User:*`、`Session:*`、`Workspace:*`、`WorkspaceMember:*` 与
  `WorkspaceInvitation:*`。需要更新角色配置中的权限，并改写此前持久化的直接权限与
  API Key 权限。
- 认证 Session 现在只使用主数据库；请移除 `AuthModuleOptions.secondaryStorage` 配置。
  API Key 默认权限与授予上限可分别通过 `apiKey.defaultPermissions` 和
  `apiKey.allowedPermissions` 配置。
- 切换 TypeScript 模块解析后，重新生成文件和迁移，确保生成的导入带有有效的
  ESM 扩展名。

服务端示例的历史迁移已替换为按当前实体生成的一份基线迁移。示例应使用全新数据库；
这份基线不用于升级执行过旧迁移的数据库。重建已有开发数据库前，请先备份需要保留的数据。

## 仓库测试

Nest Boot 版本 8 使用基于 SWC 的 Vitest 替代 Jest。贡献者可以通过
`pnpm test` 和 `pnpm test:e2e` 运行单元测试与端到端测试。
